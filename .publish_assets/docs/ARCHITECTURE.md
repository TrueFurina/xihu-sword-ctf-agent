# 架构说明 · Architecture

## 总览

```
                         ┌──────────────┐
      题面/附件 ───────▶ │  supervisor  │  步骤预算 + 工具优先纪律 + 提交闸门(fail-closed)
                         └──────┬───────┘
                                │ 静态分析优先
                 ┌──────────────┼───────────────────────┐
                 ▼              ▼                        ▼
         ┌────────────┐  ┌──────────────┐        ┌──────────────┐
         │  presolve  │  │  解题 agents  │        │  math_engine │
         │ 静态分析器  │  │ crypto/misc/ │        │  数学推理补充  │
         │ 49 确定性技能│  │ web/rev/pwn  │        └──────────────┘
         └─────┬──────┘  └──────────────┘
               │ miss 才升级
               ▼
         ┌────────────┐
         │    LLM     │  白名单 + token 预算 + 墙钟止损
         └────────────┘
```

## 关键组件

| 组件 | 职责 |
|---|---|
| `supervisor` | 步骤预算、工具优先纪律、提交闸门（fail-closed） |
| `presolve` | 静态分析层，并行扇出 49 个确定性技能 |
| `crypto/misc/web/reverse/pwn` agents | 各管一类题型 |
| `math_engine` | 数学推理补充（数论、格等） |
| `ctfplatform` | 赛题平台交互（题面/附件/靶机/提交） |
| `scripts/_honesty_scan.py` | 诚实水位扫描，拦截虚假战报 |
| `scripts/_merge_gate.py` | 合并闸门：KPI 不降 + 全量 pytest |

## 确定性优先原则

1. 一切能枚举的套路先走 `presolve`，不调用 LLM。
2. LLM 仅在 static miss 后介入，且受三重约束（白名单 / token 预算 / 墙钟）。
3. 提交前经 fail-closed 闸门；请求出错即硬失败。

## 治理（三铁律）

- **工件可信**：只信可复现命令 + 落盘工件。
- **裁判分离**：实现者不当自己裁判；诚实扫描器独立验证表述。
- **启动即门禁**：预处理钩子 + 诚实扫描 + 合并闸门，在入口处拦截风险。

## 发布模型（双仓库）

- 内部作战仓（私有）持续开发。
- 发布脚本 `scripts/release_export.py` + 同步脚本做 fail-closed 脱敏自检，
  剔除内部目录/真 flag 附件，再同步到公开仓 `truefurina/xihu-sword-ctf-agent`。
- 真 flag、密钥、内部复盘**永不入公开仓**。
