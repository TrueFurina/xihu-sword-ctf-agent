# AI Agent 解题夺旗赛完整落地建设方案

AI Agent 解题夺旗赛”，聚焦人工智能技术在网络安全复杂任务中的实际应用能力。赛事以 CTF 解题为载体，模拟真实工作场景中 “人机协同” 完成安全分析、信息处理、漏洞判断、工具调用和结果验证的过程。
本赛制不再单纯考察选手个人手工解题速度，而是重点考察参赛队伍如何设计、训练、调度和优化 CTF Agent，使其在大量任务、高频反馈和有限时间内协助人类完成复杂问题拆解与自动化处理。选手需要充分发挥 AI 在信息理解、路径规划、批量尝试、代码生成、日志分析和持续迭代中的作用，同时体现人类在目标设定、策略判断、过程监督和结果复核中的价值，线上初赛
竞赛模式
线上初赛采用限时解题模式。比赛期间，平台将分批开放大量 CTF 题目，题量设计明显超过人工手工完成能力，旨在引导参赛队伍依靠自研 Agent 进行批量分析、自动尝试、环境交互和持续提交，体现 AI 在复杂任务处理中的效率优势。
比赛仅开放统一 API 接口。参赛队伍需通过 API 获取题目信息、访问题目环境、提交 Flag 和获取反馈结果。平台不提供传统网页端手工做题入口。
比赛过程中，参赛队伍可以持续与自行构建的 Agent 进行交互，包括设定任务目标、调整解题优先级、查看运行状态、优化提示词、分析执行结果和修正策略方向。赛事允许选手在合理范围内参与 Agent 的监督、引导和策略优化，鼓励形成符合真实安全工作场景的人机协同模式。
赛事不对网络环境作强限制，但参赛行为应遵守比赛规则，不得攻击赛事平台、干扰其他队伍或利用非授权方式获取题目答案。
赛题与评分
赛题以 CTF 入门至进阶方向为主，可覆盖 Web、Misc、Crypto、脚本分析、漏洞利用基础等类型，重点考察 Agent 对题目描述、附件、环境反馈和错误信息的综合处理能力，以及选手对 Agent 解题过程的组织、监督和优化能力。
比赛采用 Flag 计分方式。参赛队伍通过 API 成功提交有效 Flag 后获得对应分数。最终排名以总得分为主要依据；若得分相同，可依次参考完成时间、解题数量、错误提交次数、API 调用效率等因素进行排序。
线下决赛
决赛评审在线下进行，分为作品答辩和专家评审两个环节。参赛队自行携带作品、文档及设备，到决赛地点进行演示答辩。需围绕其 CTF Agent 进行展示，包括系统架构、核心模块、人机协同流程、任务调度策略、自动化解题能力、典型题目复盘和现场问答。答辩时间为 20 分钟，包括 PPT 陈述、演示、测试与专家提问，专家会现场检查源代码。评审专家对每个竞赛作品实行分项打分，集体讨论，结合线上成绩与答辩表现综合评定，最终确定每支队伍的奖金。
测试赛
在初赛比赛前设置线上测试赛，时长 2 天，主要用于参赛队伍熟悉平台规则、调试 API 调用流程、验证 Agent 与比赛平台之间的交互方式，并优化人机协同工作流程。测试赛不计入排名，仅用于技术验证。



# AI Agent解题夺旗赛完整落地建设方案
结合你给出的赛事规则，我将从**队伍参赛落地方案、赛事平台侧建设、人机协同工作流、比赛全周期技术细节、答辩准备**5个完整维度给出可直接落地的全套设计，完全匹配赛制的API唯一接入、大规模题量、人机协同的核心要求：
## 一、参赛队伍CTF Agent完整技术架构
赛制明确比赛仅开放API入口、题量远超人工完成上限，核心目标是搭建一套**人管控、Agent批量解题、可动态调优**的多智能体解题体系，整体采用「四层解耦架构」，完全适配线上初赛的竞赛规则：
### 1. 顶层：人机协同调度中枢（人类工程师的管控入口）
这是整套系统的核心管控节点，完全对应赛制要求的人类目标设定、策略监督、结果复核能力：
1. **全局任务看板**：同步赛事API返回的全部题目清单，自动完成Web、Misc、Crypto、Pwn、Reverse的赛道分类，支持选手手动标记题目优先级、锁定高分值目标。
2. **风险分级审批机制**：严格对齐真实攻防场景的人机权责边界
    | 风险等级 | 操作类型                               | 人机规则                                                     |
    | -------- | -------------------------------------- | ------------------------------------------------------------ |
    | 低风险   | 题目信息读取、目录扫描、静态文件分析   | Agent自动执行，仅留存运行日志供人员回溯                      |
    | 中风险   | EXP代码运行、靶机端口爆破、漏洞探测    | Agent执行前自动推送告警，选手10分钟内无操作则自动终止任务    |
    | 高风险   | Flag提交、长链路渗透、靶机高危指令下发 | 必须人工确认后才可执行，杜绝Agent误提交、高频发包触发平台封禁 |
3. **赛事API代理层**：隔离Agent和赛事平台的直连访问，统一管控全部API请求，内置流量限流、请求重试、异常兜底能力，规避比赛规则禁止的高频调用、平台攻击行为。
    预置赛事标准API全量适配：
    ```
    GET /api/challenge/list 获取全量赛题列表
    GET /api/challenge/{cid} 获取单题附件、环境地址
    POST /api/submit 提交Flag、获取判题反馈
    GET /api/ranking 获取实时排行榜
    ```
4. **断点恢复模块**：比赛过程中Agent宕机、算力中断时，自动读取解题快照，接续剩余解题流程，不会丢失已经完成的侦查结果。

### 2. 规划层：全局解题大模型（CTF指挥官Agent）
对标国际开源CTF Agent框架的指挥官设计，仅负责宏观路径规划，不执行底层渗透操作：
1. **题目研判**：接收赛题描述、附件文件之后完成赛道分类、难度预估，输出完整的攻击执行路线；
2. **任务分发**：将解题任务下发给对应方向的专家子Agent，例如Web类题目派发给Web专项Agent，密码学题目交给Crypto专家Agent；
3. **动态策略调整**：接收靶机返回的报错反馈，判断当前解题路径已经走入死胡同，主动切换攻击思路，例如SQL注入探测失败后，自动跳转XSS路径；
4. **一血抢占管控**：实时监控榜单，优先调度高分、低解题数量的题目，最大化队伍得分收益。

### 3. 执行层：专精方向专家Agent集群
为每一个CTF赛道配置独立的专家智能体，多支Agent并行运行，抵消单一大模型幻觉、解题卡顿的问题：
| Agent类型        | 核心能力                                            | 配套工具库                                     |
| ---------------- | --------------------------------------------------- | ---------------------------------------------- |
| Web解题Agent     | 源码审计、路由扫描、Payload构造、中间件漏洞利用     | dirsearch、sqlmap、Nmap、Burp Suite 自动化调用 |
| Crypto解题Agent  | 古典密码破译、流密码分析、RSA/ECC大数分解、哈希碰撞 | SageMath、OpenSSL、自定义密码爆破脚本          |
| Misc取证Agent    | 流量包解析、图片隐写、压缩包伪加密、内存数据提取    | binwalk、foremost、steghide、Wireshark         |
| Pwn二进制Agent   | 栈溢出ROP构造、glibc漏洞利用、沙箱绕过              | pwntools、gdb、radare2                         |
| Reverse逆向Agent | IDA反汇编、伪代码解读、字符串解密、逻辑补丁         | Ghidra、angr符号执行引擎                       |

Agent底层全部运行于独立Docker沙箱环境，每道题目对应一个隔离容器，靶机环境、攻击工具互相隔离，避免题目之间的环境污染。
### 4. 记忆知识库层
实现队伍全部解题经验的沉淀与复用，大幅提升后续题目的解题速度：
1. **题目样本库**：保存全部已经解出的题目、完整攻击链路、Flag，完成同类题目的知识迁移；
2. **CTF漏洞知识库**：收录全量常见CVE漏洞、CTF经典题型的解题思路，Agent发起攻击前自动检索匹配的利用方案；
3. **平台反馈知识库**：记录赛事靶机返回的全部报错信息，例如WAF拦截特征、靶机环境的版本限制，后续Agent自动规避同类错误。

## 二、全周期比赛落地流程
### 1. 测试赛阶段（2天赛前调试窗口）
完全依托测试赛完成整套Agent的全链路验证，赛事给出的测试环境是最佳调优机会：

4. **算力资源兜底配置**：初赛题量极大，建议搭建多机GPU集群，部署多套Agent副本并行解题，单题目同时启动3‑5个不同模型的Agent并行探索，最大化解题上限。

### 2. 线上初赛运行阶段
比赛开启之后，整套系统按照标准的人机协同闭环持续运行：
1. **初始拉取**：队伍通过API一次性拉取全部开放赛题，调度中枢完成题目分值、难度排序；
2. **并行分发**：按照优先级将题目下发到对应赛道的专家Agent，多道题目同步启动解题；
3. **环境交互**：Agent调用配套安全工具完成漏洞探测、EXP编写、靶机交互，全部执行结果回传给指挥官Agent；
4. **结果校验**：指挥官Agent拿到初步Flag结果后，先将结果送入人工复核环节，工程师确认攻击逻辑无异常之后，发起Flag提交请求；
5. **赛事反馈回流**：接收平台判题结果，靶机返回的报错信息同步写入知识库，Agent自动调整解题策略，错误提交不会重复发生；
6. **排名动态响应**：每5分钟拉取一次实时排行榜，动态切换解题优先级，优先抢占还没有被解出的高分题目。

   # 分阶段完整落地方案：初赛开源底座快速落地、决赛自研拉开技术差距
   该路线完全适配你当前AI Agent夺旗赛的全部赛制规则，将比赛拆分为测试赛、线上初赛、线下决赛三个递进阶段，兼顾初赛算力与解题效率、决赛原创性与答辩竞争力，同时严格规避赛事的知识产权、代码合规风险，以下为完整可落地的实施规划：
   ## 一、整体参赛策略顶层设计
   ### 核心分工原则
   1. **测试赛、初赛：以开源组件为底座，完成赛事场景适配**
     初赛的核心目标是拿到足够高的分数完成晋级，你不需要从零开发整套系统，优先复用成熟开源工程完成底座搭建，把全部开发精力投入**赛事API适配、人机协同管控、算力调度**三类和赛制强绑定的工程改造，在有限时间内跑出稳定的解题能力。
   2. **线下决赛：完成全链路自研迭代，打造差异化技术壁垒**
     决赛评委的打分重点考察原创设计、架构创新、工程落地能力，初赛使用的开源基座仅作为技术参考，决赛版本需要交付完整自研的核心模块，搭配大量实测数据、现场演示证明项目的独特价值。
   ### 赛制匹配的技术分工边界
   | 比赛阶段      | 开源组件占比 | 自研开发占比 | 核心目标                                                     |
   | ------------- | ------------ | ------------ | ------------------------------------------------------------ |
   | 测试赛（2天） | 90%          | 10%          | 完成API连通验证、Agent基础解题能力基线测试、人机流程打磨     |
   | 线上初赛      | 60%‑70%      | 30%‑40%      | 稳定完成海量赛题的批量解题，保障高分晋级，完成全量赛道的解题能力验证 |
   | 线下决赛      | ≤30%         | ≥70%         | 输出具备完全原创性的CTF Agent系统，形成可以面向护网、政企红蓝对抗的落地方案 |

   ## 二、测试赛阶段：开源底座快速搭建，完成全链路调试
   测试赛唯一的定位是技术验证，不需要开发创新功能，优先完成整套系统的跑通，为初赛打好基础，落地组件清单如下：
   ### 1. 基础设施底座（100%开源复用）
   直接选用成熟开源工程完成底层能力搭建，仅调整参数适配赛事环境：
   1. **分布式算力调度**：Celery + Flower，赛事海量题目需要并行解题，依托该框架实现任务分发、断点续存，你只需要新增简易的优先级调度插件。
   2. **隔离沙箱靶机环境**：xctf‑sandbox + Firecracker微虚拟机，每一道CTF题目分配独立运行容器，防止解题样本互相污染，所有EXP代码都在沙箱内运行验证。
   3. **日志存储检索**：ELK全家桶，留存靶机返回的报错信息、Agent运行全量日志，自动提取WAF拦截特征、靶机环境特征，用于后续解题策略迭代。
   4. **基础CTF工具库**：pwntools、SageMath、Ghidra、Nmap，全部工具封装到沙箱环境当中，赛事侧流量统一经由网关转发。
   ### 2. 大模型与解题Agent基座（开源基座微调）
   1. 大模型底座：选用Qwen‑CTF、Llama‑CTF已经完成CTF方向微调的开源权重，使用LoRA低秩微调注入历年CTF真题、靶机报错样本，不需要从零训练大模型。
   2. 专项解题子Agent：直接复用pwnagent、CrypTool‑Agent的基础能力，针对Web、Misc、Crypto赛道完成适配，补齐赛事题目对应的解题链路。
   3. RAG检索知识库：基于OpenCTF‑RAG开源项目搭建CTF漏洞题库、题型图谱，使用Neo4j存储CTF题型的依赖关系，从根源降低大模型幻觉输出错误Payload的概率。
   ### 3. 初赛专属赛事适配模块（初赛阶段首批自研内容）
   该部分为比赛的核心适配功能，属于自研开发，是初赛稳定运行的核心：
   1. **赛事API统一代理网关**：赛事仅开放API入口，所有队伍交互流量必须由网关中转，内置流量限流、自动重试、Flag提交风控能力，严格遵守平台调用速率限制，规避IP封禁的风险。
   2. **基础人机审批规则**：设计三级风险管控机制：低风险扫描任务自动运行、漏洞探测弹窗告警、Flag提交强制人工确认，大幅度降低错误提交次数。
   3. **简易榜单算力调度模块**：定时拉取赛事排行榜，优先分配算力到高分、未被解出的题目，完成初赛阶段的基础博弈策略。
   ### 4. 测试赛验证闭环
   测试赛的两天时间内完成全部校验工作：
   1. API全链路压测，确认鉴权、题目拉取、Flag提交全流程可以稳定运行；
   2. 选取Web、Misc、Crypto三类典型测试题目，验证Agent完整解题闭环，统计平均解题耗时、Flag提交准确率；
   3. 打磨人机协同工作流，确定选手人工介入的触发阈值。

   ## 三、线上初赛：开源底座深度改造，稳定获取高分晋级
   初赛的算力需求远高于测试赛，海量赛题远超人工解题上限，初赛的工程重心是在开源底座之上完成赛事专属的优化迭代，最大化解题效率：
   ### 初赛完整工程架构
   ```
   赛事API代理网关（自研） → Celery分布式调度集群 → 多赛道专家Agent集群 → Docker沙箱运行环境 → CTF专属RAG知识库 → 人机协同管控面板
   ```
   ### 初赛重点自研优化方向
   初赛阶段你可以在开源基座上完成4类赛事定向优化，拉开和普通参赛队伍的差距：
   1. **攻防博弈算力调度引擎**：升级测试赛阶段的简易调度模块，实现动态算力倾斜：实时监测排行榜，对于高分、解出人数极少的题目分配多组并行Agent，对于大量队伍通关的低价值题目降低算力投入，最大化队伍的得分上限。
   2. **解题经验闭环迭代模块**：比赛过程中完成的全部解题链路、靶机返回的报错样本自动入库，后续同类型题目Agent可以直接迁移历史解题经验，解题速度随比赛进程持续提升。
   3. **多级队列的Agent并行探索机制**：参考CTF攻防赛事成熟的多级队列调度方案，单道题目可以同时启动3‑5个不同模型的Agent并行探索解题路径，大幅降低单Agent陷入解题死胡同的风险。
   4. **全链路流量风控体系**：完善API网关的风控能力，自动动态调整请求频率，赛事平台出现限流提示时自动降速，避免队伍IP被封禁。
   ### 初赛参赛合规注意事项

   第一层：题目附件、源码基础信息检测；
   第二层：Payload合法性静态检测；
   第三层：沙箱靶机真实运行验证；
   第四层：Flag人工复核。
