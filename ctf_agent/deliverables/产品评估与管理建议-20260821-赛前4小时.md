## 1. 产品定位评估

### 1.1 定位一致性

项目定位经历了清晰的收敛过程，这一点做得很好：

| 版本 | 定位 | 结果 |
|------|------|------|
| v1.0 | 5 子 Agent + 并发速度优先 + Grafana/gVisor/向量库 | ❌ 重、慢、赌模型 |
| v2.0 | 1 主 1 监 + **解出率优先** + 步骤级校验 + 砍重型组件 | ✅ 正确战略转身 |
| 攻坚轮 | 不赌 LLM 写攻击代码，**5 类确定性攻击链兜底** | ✅ 水位 28.6%→89%→100% |

**评价**：这是教科书式的"成本最低的差异化"——没有追求"更强的 LLM"，而是把高频题型（RSA 变种/LFSR/多层编码/隐写）做成确定性攻击链，绕过了模型"写攻击代码收尾"的刚性短板。作为竞赛产品，**这个差异化是真实且可答辩的**（§5 创新点有代码佐证）。

### 1.2 产品目标体系（三层口径，必须分层管理）

当前存在**三层解出率口径**，这是产品管理上最需要"定音"的事——口径不统一会让决策、复盘、答辩全部失真：

| 口径 | 数值 | 含义 | 用途 |
|------|------|------|------|
| 模型自主水位 | 33%（2/6） | 纯 LLM 推理，独立答案校验 | 答辩诚实底稿 |
| 组合水位 | 89%（8/9）→100%（9/9） | 模型 + 确定性攻击链 | 赛中预期锚定 |
| 平台 accepted | 未知（未实战） | 平台唯一事实源 | **赛中记账唯一标准** |

**管理要求**：赛中以"平台 accepted"为唯一记账源；复盘时三层分开统计；答辩统一用诚实口径（33% + 确定性链贡献说明）。

## 6. 赛时作战管理建议（14:00–17:00）

### 6.1 角色分工（现场执行模型）

| 角色 | 职责 | 注意 |
|------|------|------|
| Agent（自动） | crypto/misc 常规题：确定性链直接解 | 触发即出，不干预 |
| 操作员（人） | 盯看板 + 手雷脚本兜底 + HARD 题手动解 | 60s 未出 → 注入 hint → 仍未出 → 上手雷 |
| 记账（人） | 只记平台 accepted | 不信 Agent 自报 |

### 6.2 决策树（已定音，赛前打印）

1. agent 自动跑（预扫秒解简单题，RSA 走 crypto_auto）
2. 60s 未解出 → 注入 hint（data/drill_hints.json）
3. 仍未解 → 操作员跑手雷秒解脚本
4. 只认平台 accepted，不恋战：单题墙钟 300s 硬上限

### 6.3 三小时节奏建议

- **0–40min**：抢分黄金期——agent 全量并行 + 操作员盯 EASY，目标先拿稳 3–5 个 accepted
- **40–120min**：crypto 深推 + HARD 题（n 分解/DLP 类），操作员主刀，agent 辅助验证
- **120–180min**：清尾——检查未提交题、核对看板 accepted 数、防遗漏
