# 答辩演示视频分镜脚本（第三件套 · v1.0）

> **用途**：决赛答辩演示视频（5 分钟）+ 现场演示备份（防翻车，R5 风险对策）
> **原则**：只演示确定性 skill + 看板 + e2e——**不实时演示平台解题**（现场平台状态不可控）
> **录制工具**：OBS / 系统录屏 | **环境**：ctf_agent 仓库，全流程用 `.venv/Scripts/python.exe`

---

## 总览

| 镜头 | 内容 | 时长 | 录制约 |
|------|------|------|--------|
| S1 | 开场 + 架构 | 30s | 架构图 + 一句话定位 |

| — | **合计** | **~5min** | 超时风险低 |

## S3 确定性秒解（60s）——能力展示（预录，防现场慢）

**画面**：本地真题 + 确定性 skill 秒解（两条线并行展示，各 30s）：

**线 A：crypto**（RSA 全套）
```bash
.venv/Scripts/python.exe scripts/_race_start.py --solve --challenge crypto_exciting_inverse
```
预期：`[presolve:crypto_auto] 命中 → flag{...} (0.8s)`

**线 B：misc/附件扫描**（flag_scan 递归扫）
```bash
.venv/Scripts/python.exe scripts/_race_start.py --solve --challenge misc_sheng
```
预期：`[presolve:flag_scan] 命中 → flag{...} (0.5s)`

**旁白稿**：
"这是确定性攻击链。RSA 全套攻击——phi_known、Hastad、共模、费马、Wiener——全部沉淀成工具，命中即秒解，不烧 LLM token。附件扫描递归处理，源码注释、UPX 混淆里的 flag 都跑不掉。"

**录制要点**：全程预录（防现场依赖/网络波动）；终端输出加粗；两线各截取"命中"瞬间。

## S4 错误分类修正（60s）——"不重试，修正"

**画面**：构造一个无数据场景（题面空 + 无附件 + 无靶机），展示系统行为：

**步骤 1**：主 Agent 拿到空数据
**步骤 2**：监督 Agent 裁决：`redirect: 数据完整性不足`
**步骤 3**：修正指令（特写）：
```
[feedback] 分类=环境失败 | 指令=止损换题，不烧额度 | 依据=附件/靶机/题面全缺 + 2 步 reason
```

**旁白稿**：
"关键设计：错误分五类——僵局、方向错、幻觉、工具失败、环境失败，每类一个修正指令。注意这里：数据不齐，系统不是重试，而是止损换题。初赛的教训是每题空转 8.4 次，现在一次就停。"

**录制要点**：可用测试用例模拟输出（`tests/test_race_fixes.py` 的沉溺保护用例）；也可直接演示 `phases` 模块的日志输出。

## S5 看板（40s）——防断网演示

**画面**：启动看板 + 浏览器打开：

```bash
.venv/Scripts/python.exe run.py --mode web
# 浏览器 http://localhost:8000
```

**预期**：任务列表 / 进度条 / flag 状态 / 耗时实时刷新；**关掉网络后再演示一次**（离线缓存版）。

**旁白稿**：
"单页看板，任务进度实时刷新。我们做了离线缓存——现场断网也能演示，这是防翻车的底线设计。"

**录制要点**：断网演示 5 秒（拔网线/关 WiFi 的瞬间录进去，评委最信这个）；状态持久化（`data/results/dashboard_tasks.json`）重启可恢复。
