## 1. 元层面止血（P0，最高优先级，先于一切）

### 1.1 封死"文档即进展"的自循环
**问题**：8/22 的"解出数 5→13→15 实证"commit，把离线真题复盘/本地题库解出数当成"项目进展"反复写文档。真实平台战绩（初赛 0）一字未动。
**行动**：
- 在 AGENTS.md 加铁律：**"任何复盘/实证/锐评文档，必须附带一条真实平台（DASCTF 正式环境）端到端跑通记录（题号+flag 已 accepted）。无此记录，禁止写'解出数提升/水位提升'类文档。"**
- 删除已将离线真题复盘（data/results/赛后真题复盘 11/12）与"项目解出数"混用的表述。离线复盘归离线复盘，单独归档，不进战报口径。
- 设"文档预算"：每写 1 份分析文档，必须对应 1 次真实平台验证动作（dry-run 或真解题）。写文档本身不产生分数。

### 1.2 假水位文档下架/标注（P0）
**行动**：
- `ctf_agent/AGENTS.md`：删除"冲第一""真实水位 89%/92%"等历史自嗨口径，改为"初赛 0 解出，能力底子在 10719/离线 11-12，真实泛化待真实平台验证"。
- 根目录 `deliverables/赛前攻坚实录-真实水位89.md` 等：标题加 `[已作废-自嗨口径]` 前缀，正文首行标注"此文档为赛前温室数字，非真实平台战绩，答辩严禁引用"。
- 保留 `test_report_honesty.py`（防 0 题报告谎报），但补一条断言：**报告含"解出数提升/水位提升"字样时，必须能引用真实平台 accepted 记录，否则断言失败**。

### 1.3 立唯一判据：GO/NO-GO 红线（P0）
**定义**：开赛（或任何比赛窗口）前，必须用真实平台跑通 **≥1 题**（flag 被平台 accepted），否则整个作战 **NO-GO**，禁止开战。
**落地**：`_race_start.py --compete` 启动时，先调 `_e2e_verify.py` 做真实平台 dry-run（list→get→下载附件→1 题真实 LLM 解→断言 accepted），失败直接 exit 1，不进入作战循环。这条已在 8/22 部分接入，需加"断言 accepted"硬卡。

## 2. 逐病灶整改（针对元锐评 8 条，只列待修/部分修项）

### 病灶7·多会话并发 —— 补 CTDE 放行漏洞（P0）
**现状缺口**：`.git/hooks/pre-commit` 逻辑——"无租约文件且无 session 标识 → 放行（单人环境）"。只要 AI 会话不 `acquire`、不设 `CT_AGENT_SESSION`，机器门禁自动让路。机器执法仍被自觉性掐开关。
**行动**：
1. 改 hook：无租约且无 session 时，**默认拒绝**（exit 1），除非显式 `export CT_AGENT_SINGLE=1`（单人调试模式，需作者本人确认无并行会话）。
2. 启动脚本/每个 AI 会话开工第一件事强制 `acquire`：`python scripts/_lease.py acquire --session $CT_AGENT_SESSION --scope "认领的文件域/**"`，完工 `release`。
3. 在 `_race_start.py` / `setup.sh` 顶部加自动 acquire（若未设 session 则拒绝启动多会话环境）。
**验证**：两个并行 bash 会话，A acquire scope=agents，B 不设 session 直接改 agents 下文件 commit → B 被 hook 拒；B 设自己 session 但改 agents（A 的 scope） → 也被拒。两拒即达标。

### 病灶3·仓库治理 —— 瘦身 .git / 清 data 噪音（P1）
**现状**：`.git` 3.8G（历史 blob 含曾入库的运行数据/明文 key 台账）、`data` 13G（题库/附件/解压产物，本就不该在仓库）。
**行动**：
1. **先备份**：`git push` 或 `cp -r .git /备份路径` 后再动。
2. 历史重写（根治 3.8G）：装 `git-filter-repo`，剔除曾入库的大路径——
   `git filter-repo --path data/race_extract --path data/handwork --path _backup_pre_cleanup.bundle --invert-paths`（按实际曾入库路径调整）。
3. 确认 `.gitignore` 已排除 `data/race_extract/`、`data/handwork/`、`data/race_tmp/`、`*.bundle`；再 `git gc --aggressive`。
4. `data/` 13G 运行产物：保留本地，确保不在 git 跟踪；评估移入 `data_archive/`（gitignore 全排除）。
5. 顶层残留小散落：`_sec_final2.txt`、`multzip2.zip`、`multzip3.zip`、`Readme.txt` → 归入 `logs/debug_artifacts/` 或 `solutions/legacy_tools/`（沿用 8/21 整理约定）。
**验证**：`du -sh .git` < 500M；`git status` 干净；`git log` 历史不含明文 key/_probe_p0_keys.py。

### 病灶5·模型供应链 —— 停止赌博（P1）
**现状**：默认已收敛 baidu 千帆（实测存活），但竞速矩阵仍引用 qwen3.8-27b/deepseek-v4-flash-0731 等**可能 404** 的模型名（见原锐评 6.2），且靠一堆快过期免费额度。
**行动**：
1. `config.py`/`run.py` 竞速矩阵：删除所有未在供应商端验证存在的模型名，只留"环境变量与模型矩阵可用性确认-20260821.md"里实测 200 的 11 路。
2. 锁定 **1-2 个稳定付费源**（充值 DeepSeek 或开阿里 qwen-plus 付费），不依赖"免费额度哪天被砍"。
3. e2e 实测存活矩阵焊进 `--compete` 启动预检：启动时对每个源打一次最小 chat completion，402/403 源自动剔除并告警，不进比赛路由。
**验证**：`python scripts/_llm_health_probe.py` 全源探活，输出仅含实测 200 源；`run.py` 启动日志无 404/402 源被路由。

### 病灶6·整改在事后 —— 焊死 e2e 门禁（P1，已部分做）
**现状**：`_e2e_verify.py` 已存在，`--compete` 已强制 e2e 预检（dc41e9a）。但未验证"赛中真跑通"。
**行动**：
1. 把"断言 accepted ≥1"写进 `_e2e_verify.py`（见 1.3），失败 exit 1 阻断作战。
2. 加一个 CI/本地门禁：`pytest tests/test_e2e_gate.py` 每次提交跑（复用 pre-commit 或独立 gate），确保 e2e 脚本本身不被改坏。
**验证**：人为让 e2e 连错平台 → `--compete` 启动即 exit 1，不进入 poller 循环。

### 病灶2·诚信 —— AGENTS.md 清理 + 报告诚实（P0，见 1.2）
**行动**：见 1.2。保留 `test_report_honesty.py` 并补"离线复盘不得冒充战绩"断言。
