## 一、一句话定位

> **一套"确定性攻击链优先 + 步骤级错误分类修正 + 分级降级调度"的 CTF 自动化解题 Agent——把 LLM 的推理能力焊死在确定性工具上，让每一步可验证、可回退、可复盘。**

### 要解决的三个真问题（对评委讲人话）

1. **LLM 幻觉**：模型会一本正经地输出假 flag、假 EXP——怎么让它"不撒谎"？
2. **空转烧钱**：模型拿不到数据时会在推理里打转，3 小时比赛变成 87% 时间空转——怎么止损？
3. **不可复现**：AI 项目的最大黑点——"这次解出了，下次呢？"——怎么让解出率可量化、可追踪？

## 二、三大创新点（每个都有代码 + 实测证据）

### 创新点 1：确定性攻击链优先（Deterministic-First Attack Chains）

**问题**：纯 LLM 解题的典型失败模式——模型"知道"RSA 攻击方法，但算不动 1024 位大数分解；模型"记得"zip 密码爆破，但不会写循环。

**做法**：把高频攻击路径沉淀为**确定性 skill 库**（25+ 个），主 Agent 入口先做**确定性预扫（PreSolve）**，命中即出，不依赖 LLM 推理：

| skill | 覆盖场景 | 实测证据 |
|-------|---------|---------|
| `crypto_auto` | RSA 全套（phi_known / Hastad e 爆破 / 共模 / 费马 / Wiener / small_e）+ 哈希爆破 + 多层编码 | 赛前测试赛 7/7 秒解；正式赛 CRYPTO 题链路验证 |
| `flag_scan` | 递归扫附件文本（含兄弟文件 + 非打印字节清理） | reverse_js / web2 / upx 秒解 |
| `web_source_audit` | CMS/服务器源码审计（joomla/wordpress/drupal 等 10 类） | 23 个正式赛 web 题附件全量审计，输出版本-CVE 候选 |
| `crypto_pkcs1_improved` | PKCS#1 padding oracle / hint 解 p / AES 提取链 | 正式赛 CRYPTO-01 解法 95% 实证 |
| `misc_bigfile_analysis` | 449MB 大文件 zip/pcapng 提速 | 正式赛 MISC 大文件题 |

**关键设计**：确定性链 ≠ 硬编码。skill 是"攻击模板 + 参数槽"，由 LLM 负责**选题型、填参数、判结果**——人机分工：LLM 做决策，代码做计算。

### 创新点 2：步骤级错误分类与定向修正（Step-level Error Classification）

**问题**：传统 AI Agent 失败后只会"重试"——同样的错犯 8 遍（正式赛每题平均 8.4 次尝试全是同一模式）。

**做法**：错误不是"没解出"一个状态，而是 5 类，每类一个修正指令：

| 错误分类 | 判定依据 | 修正指令 |
|---------|---------|---------|
| 僵局 | 连续 3 步无工具调用 | 强制转工具：下载附件/探测靶机 |
| 方向错 | 工具输出与预期不符 | 换攻击面（如 RSA→AES） |
| 幻觉 | 无工具证据报 flag | **拒绝**：没有工具证据的 flag 不算数 |
| 工具失败 | 命令超时/报错 | 换工具实现/降级 |
| 环境失败 | 附件 403/靶机不通 | 止损换题，不烧额度 |

**证据**：`phases.extract_flag` 无工具证据即拒 + `flag_checker` 实测拦截 81 个幻觉 flag——**纪律被数据验证**。

### 创新点 3：分级降级调度（Tiered Model Routing + Race Matrix）

**问题**：重型模型贵且慢，简单题用重型模型是烧钱；全部题用轻量模型又解不出难题。

**做法**：两层调度——
1. **分级降级**：attempt 0-1 用轻量（V4-Flash），HARD/VERY_HARD 或卡壳才升级重型（V4-Pro）——简单题不烧 reasoner。
2. **竞速矩阵（ultra）**：11 路实测存活 LLM 源（智谱/Kimi/豆包/千帆/MiMo/讯飞/百炼…）并行竞速，剔除 402/403 失效源，熔断自动切换。

**证据**：`_llm_health_probe.py` 实测 11 源 200 存活矩阵已落库（`bd9e0cf`）；`_should_upgrade_heavy()` 收敛判定 9 例测试全绿。

## 四、诚实叙事（ADR-2：0 解出主动说明，讲成"工程验证的转折点"）

> **答辩被追问"正式赛 0 解出"时，不回避，按这个三层结构讲：**

1. **承认事实**：正式赛 62 题 0 accepted——这是平台权威口径，我们藏不住也不藏。
2. **讲根因（不是能力，是流程）**：DasCTF 平台 API 字段与代码假设错配（附件/靶机字段名差异）→ 全题拿不到数据 → 空转。**修一行字段名就能救回整场**——这是验证缺位，不是解题能力缺位。
3. **讲转折**：赛后 12 道真题复盘 11/12 = 91.7% 解出（真实环境重放）；10719 题真实解出 `flag{S0_G00d_J0B_RUA}` 证明**全链路能力存在**；e2e 验证脚本、字段级解析、提交失败区分三项 P0 已修复并有测试证据。

**一句话总结**：**"我们为 0 分付了学费，买到了三样东西——字段级 e2e 验证、错误分类修正、诚实度。决赛我们带着这三样来。"**

## 七、创新性声明（答辩评委"这有什么创新"标准答案）

1. **确定性攻击链优先** vs 纯 LLM 解题：我们把"会做的题 100% 解出"与"不会做的题靠推理"分层——这是工程可信度设计，不是 prompt 技巧。
2. **步骤级错误分类** vs 简单重试：把 Agent 失败从"黑盒"变"可归因、可修正"——对标学术界对 LLM Agent 可观测性的呼吁。
3. **分级降级调度 + 11 路竞速**：成本与解出率的帕累托优化，且全部实测存活源，非纸面配置。
4. **诚实数据文化**：只认平台 accepted，自报水位一律禁用——这在"AI 自嗨"圈子里是稀缺资产，本身就是卖点。
