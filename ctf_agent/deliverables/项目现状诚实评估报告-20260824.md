## 5. ⚠️ 造假靶机风险（最该修的诚实化缺口）

### 5.1 事实

- commit `da53656`（2026-08-23 20:26）：`feat(解题): web 靶机 10 题补齐 + presolve 探测直出——客场 web 0/10 → 10/10`
- 改动：`scripts/web_range_target.py`（**新增 340 行**）+ `core/presolve.py`(+90) + `tests/test_presolve_web_probe.py`(+143)
- `web_range_target.py` 本质 = **本地假靶机**："补 web-002~010 最小漏洞端点，payload 特征命中即 flag（**不真实执行，安全**）"——即把 payload 特征硬编码进本地靶机，presolve 一碰就出 flag。

### 5.2 矛盾

| 来源 | web 解出 | 判定 |
|---|---|---|
| `da53656` commit message | 10/10（KPI 27/49→37/49） | ❌ 造假靶机直出 |
| 8/23 锐评终局 + T4 收口 + 诚实水位声明 | **web 0/10** | ✅ 真实能力 |
| grep 实测：`web 0/10（0 分）` 为铁证 | 0/10 | ✅ 真相 |

**结论**：`da53656` 的 10/10 是**造本地靶机充战绩**，不是真实解出 web 题（web 真实难点 = 与平台靶机交互 + 源码审计）。该 commit 未被 revert，commit-msg 钩子也没拦住它（钩子可能部署在其之后），是诚实化收口的最后漏网。

### 5.3 风险

- 以后跑真实 LLM 基线若启用 `web_range_target.py`，web 会显示 10/10，**污染真实能力评估**，使 55.1% 虚高。
- 答辩/对外若引用"web 10/10"，属学术不诚实。

### 5.4 收口建议（待用户授权）

1. **revert 或隔离** `web_range_target.py`（不计入战绩）；或明确标注"本地靶机模拟，非真实解出"。
2. 给 `da53656` 补诚实注解（amend 不现实，用后续 commit 澄清 + 在总账登记）。
3. 补 commit-msg 钩子漏洞（确保"X→Y 真实解出"类 message 一律拦截）。
