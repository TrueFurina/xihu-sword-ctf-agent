## 三、原复盘漏诊的第⑥层根因（最致命，原五层全没提）

**现象**：10719 解出正确 flag，但 `dasctf.py:342` 的提交逻辑：

```python
data = await self._request("POST", "submit", json_body={...})
if not data:
    return SubmitResult(detail="提交无响应（fail-open）")   # ← 真实错误被吞
```

`_request` 在 HTTP 4xx（鉴权/参数错）、5xx 重试耗尽、网络异常时**返回 None 并吞掉真实错误**（仅记日志）。`submit_flag` 把它笼统成"提交无响应"。

**后果**（poller 侧）：
- poller `_submit_with_retry` 把"提交未通过"计入 `consec_fail`，**连续 5 次即熔断**。
- 10719 的 5 次提交全是**请求层故障**（可能平台限流/5xx/网络抖动，race.log 末尾大量 429），但被当成"flag 错误"累计 → 熔断 → **正确 flag 被静默丢弃**。
- 全 race `accepted=True` = 0，**至少有一题（10719）是本可得分却被提交链路坑掉的**。

**含义**：即使修好根因①（拿得到题面/靶机），只要提交链路还在 fail-open 吞错，解出的题照样交不上去、照样 0 分。**这是比"拿不到题面"更隐蔽的杀手，原复盘完全漏诊。**
