# 先易后难比赛策略（锐评「没有先易后难拿分策略」修复——2026-08-22 沉淀）

> 正式赛 0 解出锐评核心：最快队伍 2 分钟/题——先扫全部题——简单题秒解拿分。
> 我们埋头 CRYPTO-01（难题）3 小时——0 解出。比赛比「解出数」不是「解出一道难题」。

## 核心原则：先易后难——每道题限时——绝不沉溺

### 一、开赛流程（前 10 分钟）
```
1. 全量拉题（exercise-list）——扫全部批次题（不只看第一批）
2. 题目分类（CRYPTO/MISC/REVERSE/WEB/PWN——按类型）
3. 难度预判（附件名/描述/大小——简单特征）：
   - 小附件（<1MB）+ crypto/misc → 简单（模板直出）
   - 大附件（>10MB）/REVERSE/APK → 难（后置）
   - 有靶机（endpoints）→ web/pwn（需交互——后置）
4. 排序：简单题优先（模板命中概率高的先做）
```

### 二、单题限时（硬规则——不沉溺）
| 阶段 | 限时 | 动作 |
|---|---|---|
| 模板识别 | 10 秒 | 命中模板 → 直接解（2 分钟目标） |
| 模板解出 | 90 秒 | 未解出 → 提交多候选（flag_extract_guard + submit_iterate） |
| 攻坚（无模板） | 5 分钟 | 未解出 → **换题**（沉溺保护——CRYPTO-01 3 小时教训） |
| 重访 | 一轮后 | 换题一轮后回来（第二梯队——不放弃但后置） |

### 三、拿分优先级（比赛目标：解出数）
```
1. 简单题全覆盖（模板命中——2 分钟/题——拿分主力）
2. 中档题（5 分钟攻坚——部分解出）
3. 难题（沉溺保护后——最后一轮重访）
```

### 四、提交策略（锐评「提交是浪费不是迭代」修复）
```
1. 解出后：flag_extract_guard 多候选（宽松/ROT13/变体）
2. submit_iterate 依次提交（accepted 即停——非猜测）
3. 50 次额度管理（错误 40 次内止损——不烧光）
```

### 五、沉溺保护机制（CRYPTO-01 教训固化）
- **单题硬上限**：5 分钟（攻坚）——超时强制换题
- **重访队列**：换题后加入重访列表——一轮后回来（不放弃但后置）
- **全局进度**：随时知道已解出数/剩余题数——以解出数为唯一指标

## 复盘对照（正式赛）
- 我们：CRYPTO-01（难题）3 小时 → 0 解出
- 策略后：先扫全部题 → 简单题 2 分钟/题拿分 → 难题后置限时
- 差距本质：不是能力——是「先易后难 + 限时 + 拿分优先」的策略缺失
