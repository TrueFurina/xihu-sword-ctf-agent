## 二、正式赛差距分析（更高难度 / 更激烈 / 大佬极速通关）

### 2.1 与「大佬极速通关」的差距拆解

| 维度 | 测试赛表现 | 大佬/正式赛要求 | 差距 |
|---|---|---|---|
| 首题速度 | 平台开赛后 ~19h 才解出首题（04:56，实际是开赛次日凌晨） | 正式赛前 30-60min 内拿分 | 🔴 差距巨大——平台接入/环境准备占大头 |
| 连续解题 | 首题后 4.5h 空档（绕远路） | 稳定 20-30min/题 | 🔴 绕远路是最大时间杀手 |
| 题型覆盖 | crypto/reverse 强、pwn 堆题弱、无靶机 web 空转 | 全题型均衡，misc/web 冷门题也要拿 | 🟠 pwn 堆题是短板 |
| 高难度题 | TheoremPlus/Fate 靠数学/逆向硬解 | 高难度题（非典型 gadget/无回显/多步链）快速识别套路 | 🟠 非常规题易卡壳 |
| 稳定性 | 单模型单路径，偶发空转/幻觉 | 多路并行 + 快速失败切换 | 🟠 需更强鲁棒性 |

### 2.2 正式赛难度升级预判（基于本次题型）

1. **crypto**：本次 TheoremPlus 是「非常规 e + 相邻素数」——正式赛可能升级为**格攻击（LLL）**、**多变量方程**、**非对称参数隐藏**。sympy 已够基础，但格攻击需 fpylll（未装）。
2. **web**：本次 POP 链/XXE/Java 反序列化——正式赛可能升级为**二次注入、条件竞争、利用链组合**（如上传+包含+反序列化多步链）。需要更深的源码审计能力。
3. **pwn**：本次 easy_uaf（非 PIE 简单）+ shopping（tcache）——正式赛可能升级为**全保护 + 新 libc（2.35+，safe-linking）**、**沙盒逃逸（seccomp）**。GDB 动态调试是刚需（本次最大短板）。
4. **misc**：本次 zip 链/编码——正式赛可能升级为**流量分析（tshark 缺失）、内存取证（volatility 缺失）、区块链**。工具链需补齐。
5. **反向**：本次 strings/反编译——正式赛可能升级为**ollvm 混淆、反调试、VM 壳**。需要 IDA/Ghidra 或 angr。

### 2.3 时间竞争核心结论

```
测试赛 7 题用 5.5h 有效时间 = 47min/题（含绕路）
正式赛若要冲榜：目标 ≤20min/题 稳定，前 3 题 ≤1h 内
→ 关键不是"解得出"，而是"解得快"：模板命中率、工具直出率、绕路率三个指标
```

## 三、经验教训沉淀（本次测试赛最值得记住的）

### 3.1 教训一：绕远路是最大敌人（shopping 案例）
- **事实**：shopping 被另一会话解出（2adf4aa），但本链不知情仍 10 版 exploit 盲打
- **教训**：多会话并行必须共享进度状态；进题前先查 hasSolved
- **已落地**：`core/solve_progress.py` 共享进度中心（postmortem high#1）

### 3.2 教训二：无 GDB 的 pwn 堆题盲打极低效（shopping free_hook 案例）
- **事实**：判据测试确证 free_hook 覆盖未命中，10 版试错
- **教训**：pwn 堆题必须本地 GDB 调试确认布局，禁止远程盲打
- **待办**：WSL 修复后装 gdb+pwndbg（正式赛前必须）

### 3.3 教训三：模型会猜答案（伪成功案例）
- **事实**：misc-008/pwn-005 出现「solved 但 validated=False」幻觉
- **教训**：flag 必须来自工具输出/附件提取/确定性计算，禁止直觉
- **已落地**：GOAL_SYSTEM_PROMPT 规则⑦（禁猜 flag）+ hallucination 标记

### 3.4 教训四：无靶机 web 题纯推理空转（本地 6 题 stuck_loop）
- **教训**：明确环境边界，无靶机直接走模板兜底，禁止空转
- **已落地**：GOAL_SYSTEM_PROMPT 规则⑩（web 空转引导）

### 3.5 教训五：成功题也有隐藏风险（不是解出就完事）
- crypto-005/misc-005 高重试才解出（路径不高效）
- Fate 绕远路（先 exec 外带失败才 Nashorn，多花 1h+）
- easy_uaf 推理跳步（误判 fgets 截断）
- **教训**：解出后要审视「是否高效、换变体是否还成立」；沉淀标准流程（pwn/java/web 已入 Goal 规则）

### 3.6 成功经验（可复用的）
1. **模板兜底链路有效**：crypto 90%+、misc 80%——先模板后自由推理
2. **平台接入打通是基础**：X-Agent-AccessKey + /slab-match 端点是做题前提
3. **逆向先行**：capstone 静态逆向（free 分支/函数指针）为利用指明方向
4. **多 provider 免费额度**：千帆 ernie-3.5 跑出 72.4%（超 DeepSeek 62.1%），成本可控

## 五、🎯 抢一血战略（正式赛核心博弈策略）

### 5.1 一血机制（手册确认）

**积分递减规则**：每解出一人扣 1%，最低 80%；分数相同按时间先后排名。
→ **一血 = 100% 全分**；第二名 = 99%，第 51 名 = 50%（递减 1% × 50 人）……

**博弈本质**：早解出 = 高分，一血 = 满分。正式赛 3h 窗口内：
- 一道 200 分题：一血拿 200 分，晚 1h 可能只剩 100-160 分
- **一血的价值 = 满分的全部，晚解的价值随解出人数指数衰减**

### 5.2 平台限制与博弈点（用户询问的「不知道有没有限制」）

| 限制 | 确认状态 | 博弈策略 |
|---|---|---|
| 题目分批开放 | ✅ 公告见「已开放赛题」+ exercise-list 有 isOpen 字段 | 进场全遍历扫 isOpen，只抢已开放的 |
| 每队 1 个 Agent | ✅ 手册确认 | 单 Agent 多会话分工（solve_progress 防重复） |
| 每题 50 次提交 | ✅ 手册确认 | 抢一血时确认后立即提交，不盲试浪费 |
| 每队 3 靶机上限 | ✅ 手册确认 | 简单题可能无需靶机（模板直出更快）|
| 提交后不可再提交 | ✅ 实测「此题已被解出」 | 一旦解出立即提交，防他人抢先 |

### 5.3 抢一血作战流程（脚本已就绪）

```
T+0min    : python scripts/_race_start.py --firstblood
            进场全遍历（exercise-list）→ 过滤 hasSolved + isOpen
T+0~1min  : 按难度绝对优先排序（VERY_EASY 无论分数先抢，同难度低分优先）
T+1~5min  : 对最简单题走模板直出（crypto/misc/web/pwn 模板兜底，不深度分析）
T+5~10min : 解出 → 立即提交（不等待确认，一血是时间竞争）
            失败 → solve_progress 标记 → 换下一题
T+10~30min: 抢下第 2、3 个一血（EASY 题）
```

### 5.4 抢一血排序算法（_scan_firstblood.py 已实现）

```python
_rank(ch) = diff_w * 100 + score * 0.1
# diff_w: VERY_EASY=0, EASY=1, MEDIUM=2, HARD=3, VERY_HARD=4
# 难度绝对优先（VERY_EASY 无论分数先抢），同难度低分优先
```

单测已验证：VERY_EASY(50) → VERY_EASY(200) → EASY(100) → MEDIUM(200)

### 5.5 抢一血经验要点

1. **先抢「模板能直出」的题**（crypto 常见模板/zip 链/morse 等），不要先啃 pwn 堆题
2. **简单题不等靶机**：isNeedInit=false 的题直接模板解，比启动靶机快得多
3. **解出即提交**：50 次限制内确认格式对就立即提交，一血窗口以秒计
4. **多会话分工抢**：每个会话抢不同难度档，solve_progress 防重复
5. **监控公告**：分批放题时，新题开放瞬间立刻抢（公告轮询接入 --firstblood）
