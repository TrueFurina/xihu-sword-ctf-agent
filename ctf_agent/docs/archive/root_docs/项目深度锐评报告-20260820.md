## 三、🔴 P0 致命问题（直接影响明天成绩 / 资格）

### P0-1 基准自欺：26/35 的"解出率"是在自己出的题上考的

- `ctf_agent/data/results/benchmark_real.json`：35 题解出 26（74%），看着漂亮。
- 但题库来自 `ctf_agent/scripts/_gen_questions.py`——**自己生成的题**，描述里直接内嵌攻击提示（如 web-001 描述明文写着"用 OR 1=1--+ 构造永真条件绕过登录获取 flag"），flag 是 `flag{caesar_shift_2026}` 这类占位值。
- **等于老师出卷、老师答题、老师批改，然后宣布自己考了 74 分。** 这个数字对明天真实赛题的预测力接近于零。
- 对照真实水位：测试赛 7 题，去伪报告自承自主解出仅 4-5 题（57-71%），其中 10664/10662 靠"并行会话协助"，10661 "存疑"。
- 更刺眼的是：`data/reports/解题报告_20260820_081918.md` 和 `解题报告_20260820_115706.md` 两份"正式赛演练报告"——**题目总数 0、解出 0**，却写着"数据来源：平台 API 真实交互记录（与网络流量/平台日志吻合）"。空数据 + 满篇合规声明，这种模板自吹如果混进决赛答辩材料就是诚信事故。

### P0-2 速度崩盘：平均 474 秒/题，最慢 1486 秒（25 分钟）

- benchmark 实测：平均 **474s/题**，max **1486s**（misc-001，重试 2 次）；7 题 `stuck_loop` 每题烧掉 500-1300s 才放弃。
- 明天赛程 3 小时（14:00-17:00）。按这个速度，串行只能过 ~20 题次尝试；即便 8 路并发，stuck_loop 会把并发槽位全部拖死——**"多题并行不阻塞"在死循环面前等于没有并行**。
- v2.0 明确"战略重心从并发速度转向解出率"——方向对，但执行上把"速度"整个扔了。**止损规则（多久判死、谁掐死）在 todo 里至今没有验收项。**

### P0-3 战略漂移：文档砍掉的"多模型竞速"，代码里扩到了 16 个

- `ARCHITECTURE_PLAN.md` 白纸黑字："砍掉 ~~多模型竞速~~"、"分级降级调度替代竞速"。
- git 历史：`3b2e7f8 批量接入8个provider——16模型竞速矩阵`、`76fdeff TokenHub 17模型实测接入——竞速池扩到12模型`、`9284b5c build_race_solver 默认6模型同时开干`。
- **规划文档和实现已经是两套战略。** 这带来三重风险：
  1. **合规风险**：参赛手册要求白名单 API。Grok/TokenRouter/TokenHub 这些渠道是否逐项在官方白名单内？`config.py:92` 显示 DeepSeek 已欠费、默认切到 baidu 千帆——**明天主力模型是免费额度的百度**，竞速矩阵里一半 provider 的赛中稳定性是未知数。
  2. **成本/熔断风险**：6 模型同开 × 474s/题，token 消耗是单模型的数倍，免费额度在赛中熔断 = 当场去世。
  3. **答辩风险**：决赛代码审查时，评委指着 plan 问"你说砍了竞速，这 16 个模型是什么？"——现成的送命题。

### P0-4 测试空洞：24,252 行代码，6 个测试函数

- `tests/` 全目录只有 `test_scheduler.py`（3 个用例）+ `test_verify.py`（3 个用例）。**6 个 test 函数护 24k 行。**
- commit 里反复出现"测试全绿""测试五路径"——绿的是 6 个用例。`core/main_agent.py`（39KB、22 个函数、4 个类，全系统大脑）没有对应的专属测试文件。
- 明天赛中任何一次热修都没有安全网，改一行错一行的概率极高。
