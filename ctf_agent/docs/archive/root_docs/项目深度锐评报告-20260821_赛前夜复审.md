## 二、🔴 P0 致命问题（直接影响明天成绩）

### P0-A 监督 Agent 在"连续失败"场景下完全失效（架构核心卖点哑火）

**证据**：`core/main_agent.py:238` 与 `core/main_agent.py:323` 在同一 solve 循环里的执行顺序死锁。

```python
# 行 238-241：stuck_count>=2 → break（先执行）
if ctx.stuck_count >= 2:
    logger.info("[%s] 连续 %d 步失败...快速放弃止损", ...)
    break

# 行 322-330：stuck_count>=2 → 调监督 apply_verdict（永远到不了）
if (step_index + 1) % 2 == 0 or ctx.stuck_count >= 2:
    verdict = await self._supervise(ctx)
    if verdict.action == VERDICT_GIVE_UP: break
    ctx.apply_verdict(verdict)  # upgrade/switch 会重置 stuck_count=0
```

**后果**：v2.0 架构的核心卖点是「1主1监：失败时监督裁决换策略/升级模型，不盲目重试」。但 stuck_count 一到 2 就 break 跳出循环，监督的 `upgrade_model`/`switch_strategy`（重置 stuck_count）**永远没有执行机会**。代码自己注释了（行 311-312）"阈值 3 永远到不了所以改 2"，但改了之后没改 238 行的 break 阈值——**问题没解决，只是搬家了**。

监督 Agent 真正能工作的只剩「每 2 步触发一次」这条路径，而那条路径在连续失败场景下根本不会发生（连续失败 2 步就 break 了）。**监督 Agent 在它最该工作的场景下是哑的。**

**修复优先级**：P0，赛前必改。把 238 行的 break 改成"先咨询监督，监督裁决 give_up 才 break"。

### P0-B 默认配置陷阱：忘 export 环境变量 = 默认走免费弱模型

**证据**：
- `config.py:92`：`llm_provider: str = "baidu"`（默认千帆）
- `config.py:98`：`light_model: str = "ernie-3.5-8k-preview"`（千帆免费弱模型）
- `setup.sh:1-50`：**全程不 set 任何环境变量**，只在结尾 echo 提示用户要 set
- 作战手册 `赛前作战手册_20260821.md:38` 明确写："必须 `export CTF_AGENT_LIGHT_MODEL=deepseek-chat`，否则 qwen3.7-plus 打 deepseek 端点 400"

**后果**：赛中如果用户只跑 `bash setup.sh` + `run.py --race`，**没显式 export**，就会默认走 baidu+ernie-3.5-8k（免费弱模型，能力远低于 deepseek-chat）。作战手册第 38 行那个"必须"是写在手册里，不是写在代码里——**最关键的模型选择依赖人记忆，不依赖配置默认值**。赛中紧张漏一行 export = 解出率腰斩。

**修复优先级**：P0，赛前必改。`setup.sh` 结尾自动 `export` 这 5 个变量，或 config.py 默认值改成 deepseek+deepseek-chat。

### P0-C 真实水位结构性水分：60% 的分子全是 EASY 模板题

**证据**：作战手册 `赛前作战手册_20260821.md:155-163` 五道真题表现：

| 题目 | 难度 | 结果 | 归因 |
|------|------|------|------|
| real_crypto_ezmult (base64+ROT13) | EASY | ✓ | python: 前缀修复后秒解 |
| real_crypto_caesar (凯撒暴力) | EASY | ✓ | caesar_bruteforce 兜底直出 |
| real_crypto_hash_brute (MD5爆破) | EASY | ✓ | hash_crack skill 爆破 |
| real_crypto_exciting_inverse | MEDIUM | ✗ | LLM 代码逻辑有误 |
| real_crypto_ezrsa (Hastad广播) | MEDIUM | ✗ | CRT+开方代码 LLM 没写对 |

**后果**：
- 3 道解出的**全是 EASY 编码/哈希/凯撒**——这些题本质上 skill 模板就能解（`caesar_bruteforce.py`/`hash_crack.py`），不需要 LLM 推理。
- **2 道 MEDIUM RSA 题 0/2 全军覆没**——这才是西湖论剑初赛的真实题面密度（手册 8.1 自己预判 Crypto 高密度 RSA 变种）。
- "60% 真实水位"是**幸存者偏差**：分子是 EASY 模板题，分母是混合难度。真实赛题如果以 MEDIUM+ 为主，按现有数据外推真实解出率可能 **<25%**。

作战手册 8.3 说"MEDIUM/HARD 题（RSA 变种）→ 需 LLM 写对攻击代码，墙钟 600s 深推"——但实测 LLM 写不对 RSA 攻击代码（exciting_inverse 和 ezrsa 都因 LLM 代码逻辑错误失败）。**墙钟给到 600s 也救不了写不对的代码。**

**修复优先级**：P0，赛前必改。MEDIUM+ RSA 题不能再依赖 LLM 现场写代码，必须把 `rsa_fermat_factor`/`crypto_coppersmith`/Hastad CRT 这些 skill 的**确定性脚本**接进 main_agent 的 fallback 路径（core/fallbacks.py），让 skill 直接出结果而不是让 LLM 重写。
