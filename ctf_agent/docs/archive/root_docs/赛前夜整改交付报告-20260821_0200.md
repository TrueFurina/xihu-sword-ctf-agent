## 三、关键修复细节

### 3.1 P0-A 监督 Agent 死锁修复

**位置**：`core/main_agent.py:240-255`

**修复前**（死锁）：
```python
if ctx.stuck_count >= 2:
    break  # ← 监督的 upgrade/switch 永远到不了
```

**修复后**（先咨询再决定）：
```python
if ctx.stuck_count >= 2:
    verdict = await self._supervise(ctx)
    if verdict.action == VERDICT_GIVE_UP:
        break
    ctx.apply_verdict(verdict)
    if verdict.action == VERDICT_UPGRADE:
        if attempt >= 2:  # 已升级过仍失败 → 放弃
            break
        attempt = 2  # 升级重型模型重试
        continue
    continue  # switch/redirect 继续（stuck_count 已重置）
```

**效果**：监督 Agent 的核心能力（upgrade/switch 重置僵局）在连续失败场景下恢复工作。

### 3.2 P0-B 配置陷阱修复

**位置**：`setup.sh:53-63` + 注册表修正

**关键发现**：注册表里 `CTF_AGENT_LLM_PROVIDER=baidu` 但 `CTF_AGENT_LIGHT_MODEL=deepseek-chat`——**deepseek-chat 打千帆端点 = 400**。

**修复**：
1. setup.sh 加 `export` + `setx` 4 个环境变量
2. 手动 `setx CTF_AGENT_LLM_PROVIDER deepseek` 修正注册表
3. 验证：模拟新 shell 读注册表，provider=deepseek + 端点模型匹配 ✓

### 3.3 P0-C RSA 确定性 fallback

**位置**：`agents/crypto_toolkit.py:272-307` + `sandbox/subprocess_executor.py:36`

**修复**：
1. `_TRIAGE_BODY` 的 RSA 分支接入 `from skills.rsa_fermat_factor import run`
2. 显式按优先级逐个尝试：phi_known → hastad → common_modulus → auto
3. sandbox 白名单加 `"skills"` 前缀允许 import
4. skill 不可用时回退到内联 small_e/wiener/common_modulus

**效果**：MEDIUM RSA 题不再依赖 LLM 现场写代码（实测 0/2 全错），改为确定性脚本直接出结果。
