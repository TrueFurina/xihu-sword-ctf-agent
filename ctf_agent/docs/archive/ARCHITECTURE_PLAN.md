## 一、项目定位（一句话）

**自研 AI 解题 Agent，面向 Web/Crypto/Misc（初赛）/Reverse/Pwn（决赛）题型，以「解出率优先 + 1主1监推理内核 + 多题并行不阻塞」冲击西湖论剑第一名。**

## 二、核心竞争策略（v2.0，解出率优先）

| # | 策略 | 说明 | 优先级 |
|---|------|------|--------|
| 1 | **解出率优先（胜负手）** | 排名看解出的题目分值，不看快几秒；把 70%+ 精力投入 Agent 推理质量、工具调用准确率、错误复盘、知识库有效性 | 🔴 核心 |
| 2 | **1 主 1 监架构** | 主解题 Agent（Plan-Act-Observe 推理内核）+ 监督反思 Agent（轻量裁决，打断僵局/切换策略）+ 领域工具包 | 🔴 核心 |
| 3 | **步骤级校验闭环** | 错误分类（僵局/方向错/幻觉/工具失败）→ 监督裁决 → 结构化修正指令，不盲目重试 | 🔴 核心 |
| 4 | **分级降级调度** | 轻量模型先试 → 失败升级重型模型（成本可控），替代多模型竞速 | 🟡 重要 |
| 5 | **多题并行不阻塞** | asyncio 任务池并行执行，不做花哨优先级/毫秒测速打磨 | 🟡 及格即可 |
| 6 | **评委演示看板** | 单页 HTML + 原生 JS 轮询（进度/耗时/flag），半天完成 | 🟡 演示加分 |

## 六、关键技术决策（v2.0）

1. **1 主 1 监**：主 Agent 走 Plan-Act-Observe；监督 Agent 轻量裁决（continue/redirect/switch_strategy/upgrade_model），每 2-3 步或连续失败 3 次咨询
2. **分级降级调度**：attempt 0-1 轻量模型（V4-Flash），attempt 2-3 重型模型（V4-Pro），成本可控
3. **步骤级校验**：StepChecker 解析工具输出关键信息 → ErrorClassifier 错误分类 → 结构化修正指令（不丢原始日志）
4. **平台 API 抽象做厚**：list/get/create_instance/get_access/download_attachment/submit/reset/destroy 全生命周期，测试赛只填实现
5. **模板降级为辅助**：payload 快速生成工具，非核心得分项；删除难度预分类器（改为轻量题型识别）
6. **统一 JSON 契约**：`{flag, confidence, evidence, error{category,detail}, supervision, duration_ms, provider, retries}`

## 九、创新点（答辩核心论据，v2.0）

1. **解出率优先的 1 主 1 监推理架构**：主 Agent 自主决策 + 监督 Agent 轻量裁决，解决「AI 解题为何失败、如何减少错误」——评委认可的真实思考
2. **步骤级错误分类与结构化修正**：僵局/方向错/幻觉/工具失败分类引导，替代盲目重试
3. **分级降级模型调度**：成本可控的解出率提升（轻量→重型渐进）
4. **全生命周期平台抽象**：未知 API 规范下的工程化适配能力
5. **多题并行不阻塞 + 单页演示看板**：工程落地完整度
