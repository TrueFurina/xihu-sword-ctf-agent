## 二、可复用教训（每条 = 一条规则）

### R1. 分类兜底必须用专用桶，不误用语义桶
- **事故**：`_finalize` 兜底分支 `elif not flag: err_category = ERR_STUCK_LOOP` 把所有"未解出 flag"归入 stuck_loop（死循环语义），实测 98.2% 案例 stuck_count=0。
- **规则**：语义桶（stuck_loop/wrong_direction/extract_fail 等）只能按明确证据归类；"未解出且无明确归因"必须归专用兜底桶（unresolved），否则污染失败桶统计。
- **验证**：`python -m pytest tests/ -k "classifier or main_agent"`。

### R2. 换 provider 模型前必须实测 HTTP 200（免费额度会耗尽）
- **事故**：qwen3.7-plus 403（免费额度耗尽）→ 换 deepseek-v4-pro-0813（当时 200）→ 8-27 实测 403（额度也耗尽）。
- **规则**：免费额度会随时间耗尽；切换默认/重型模型前，先用最小请求实测目标模型 HTTP 200（`httpx.post` 到端点 + 模型名）。
- **命令**：`python -c "httpx.post(url, json={'model':M,'messages':[...]})"` 看状态码。

### R3. 环境变量必须用 provider 专属命名
- **事故**：设 `CTF_AGENT_HEAVY_MODEL=qwen3.7-flash` 无效——`get_model_for_attempt` 读的是 `CTF_AGENT_{PROVIDER}_HEAVY_MODEL`（如 `CTF_AGENT_QWEN_HEAVY_MODEL`），仍升级到 403 的 deepseek-v4-pro-0813。
- **规则**：设 provider 相关环境变量前，先 grep 代码确认变量名（`grep -rn "os.getenv" llm/client.py config.py`）。

### R4. lease acquire scope 需双基准（仓库根 + 相对 ctf_agent）
- **事故**：acquire scope `ctf_agent/core/main_agent.py`（仓库根）被提交门禁拦截——检查用相对路径 `core/main_agent.py`。
- **规则**：acquire lease 时 scope 同时给仓库根与相对两种基准：`--scope "ctf_agent/core/main_agent.py" "core/main_agent.py"`。

### R5. commit message 前缀写明性质（任务板门禁）
- **事故**：纯 `[无任务]` 前缀被任务板门禁拦截（2026-08-28 包工头强化）。
- **规则**：功能/修复/解题类挂 `T-xx`（TASK_BOARD 认领）；治理/文档/门禁类用 `[无任务:治理]`/`[无任务:文档]` 写明性质。

### R6. goal_log 数据口径（字符串化 dict）
- **事故**：`error` 字段是字符串化的 dict（非 dict），直接 `isinstance(e,dict)` 提取失败（统计出 0 条 vs 实际 113 条）。
- **规则**：解析 goal_log 时先 `ast.literal_eval` 还原 error 字符串；失败桶从 `error.category` 提取（status 字段全为 'None' 不可用）；`supervise_test` 是测试数据需剔除。

### R7. presolve 直出能力 ≠ 主 Agent 场景触发
- **事故**：anwang_crypto1 的 goal_log 记录 presolve=0、wrong_direction 66 条，但单独跑 presolve（force=True）直接直出。
- **根因**：`presolve_attempted` 标记去重——首次失败（附件下载 429）被标记后，后续不 force 直接跳过；49030b5 `_attachments` 兜底已修。
- **规则**：presolve 路由触发依赖附件完整性 + 未被 attempted 标记污染；排查"presolve 未触发"先查附件下载与标记状态。
