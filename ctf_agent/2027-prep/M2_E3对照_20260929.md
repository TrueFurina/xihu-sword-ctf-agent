## 3. 🔴 关键发现（含自我纠正）

### 3.1 E3 对「能否解出」零边际贡献
两组都是 **0/8 解出**。E3 注入证据与否，LLM 主链路在这批题上**一道都解不出**。E3 不是解 CTF 的能力开关。

### 3.2 反直觉：E3 OFF 反而更费 token（+14.0%）
**纠正我启动时的预期**：我当时判断「E3 ON 每步 prompt 更大 → 默认化有 token 代价」。实测相反——关掉 E3 后 8 题总 token **从 335K 升到 382K（+14%）**。
机制解释：E3 ON 时证据注入让 LLM 更早聚焦攻击链 / 更早触发 `race_abandon` 止损（例如 mceliece 在 ON 组 32K 即 race_abandon，OFF 组空转到 80K 才 budget_exceeded）；E3 OFF 时 LLM「证据不进脑」反而**盲目重试更久、空转更多步**。即 E3 的降本效应来自「防空转 + 更早止损」，而非「更大 prompt 更费」。

### 3.3 错误分类同构
两组错误分布一致：ON = `race_abandon:6 + budget_exceeded:2`；OFF = `race_abandon:5 + budget_exceeded:3`。E3 OFF 时 mceliece 从 race_abandon 变成 budget_exceeded（空转更久烧穿 80K），其余同构。

## 4. 诚实声明（必带）

- 🔴 **N=8 子集**：仅失败题，非全 17。**E3 对 presolve 9 题无影响**（presolve 是静态分析，不进 LLM），故 E3 的「省 token」结论只覆盖主链路失败题，不敢外推到全池。
- 🔴 **报告 `integrity` 字段系统性瑕疵**：两份报告的 `truncated/被外部掐断` 把 `race_abandon`/`budget_exceeded` 都算成「被基础设施掐断」「interpretable:false」——这是报告生成逻辑缺陷。实际 8 题**全部真跑过**（日志：zkpok 跑 7 步才早停、mceliece 跑满 80K）。「机制终结（早停/预算）」≠「基础设施未执行」，必须分拆。
- 🟡 **zkpok 留白已补**：ceiling8（B 方案）时 zkpok 排第 8 被全局预算连坐 0-token 未测；本组（独立 800K 预算）zkpok 正常跑 25,881 token、7 步后 race_abandon——**0/8 中 zkpok 这一道现已充分测试**。
- 🟡 **模型是瓶颈**：deepseek-flash 免费档，8 道全失败的根因是「攻击链未命中 / 连续同动作空转」，E3 只改上下文，不改模型能力上限。

## 5. E3 默认化判定与固化建议

| 维度 | 结论 |
|---|---|
| 解出贡献 | **0**（两组都 0/8），E3 不决定能否解出 |
| 成本贡献 | **正向**：E3 ON 省 ~14% token（防空转+早止损） |
| 质量贡献 | 防「证据不进脑」导致盲目重试（hwsim/mceliece 在 OFF 组空转暴增） |
| 副作用 | E3 ON 每步 prompt 更大（理论），但实测被「少空转」抵消且有净省 |

**建议（不强行改默认，记证据）：**
1. **生产默认保持 OFF**（`main_agent.py:160 e3_enabled=False`），按需 `CTF_AGENT_E3=1` 开启——避免对 presolve 题（占多数）无谓增大 prompt。
2. **Benchmark/评测保持强制 ON**（`benchmark_heldout.py:458`）——评测要测「证据注入后」的真实表现，且实测 E3 更省 token。
3. **后续修报告 `integrity` 字段**：把「机制终结（race_abandon/budget_exceeded）」与「基础设施未执行（零 token 真没跑）」分拆，否则所有 held-out 报告都被误标 `interpretable:false`。
4. **不把 E3 当能力突破项**：它是工程降本/防空转项，规划里归 M2 工程优化，不写入「能力边界」叙事。
