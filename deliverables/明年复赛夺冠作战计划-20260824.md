## §1 架构层（速度 + 覆盖碾压）

### 1.1 单接入点多模型竞速（吃规则红利）
- **规则边界**（选手群报告实测）：官方"一支队伍只能一个 Agent 接入平台"；subagent 是否算 Agent 有争议；"不鼓励人工引导"。
- **设计**：对外暴露**单一接入点 Agent**（合规），内部编排 = 主 Agent（调度）+ 监督者（零写权限止损）+ N 个题型子 Agent（crypto/web/misc/reverse/pwn）。这吃满 subagent 争议红利，不违反字面规定。
- **pass@k 每题并行**：参考 hydra——每题同时跑 baidu/qwen/deepseek-reasoner 多模型，先拿到合规 flag 者胜，缩短单题墙钟。

### 1.2 并发竞速扩车道
- 当前 worktree 3 车道（有架构骨架）。实测并发题量上限（对标 verialabs 默认 10 并发），把 3 → 10。
- 毫秒级测速埋点（已部分存在），决赛演示时做"速度碾压"直观证据。

### 1.3 补环境缺件（已闭环 specialcurve2 → 14/15）

> 2026-08-24 P0 实测：specialcurve2 已用 factordb + 已验证 writeup e 兜底解出（不装 PARI）；misc vnctf_flag 经 4 类纯 Python 解码全 NO，需题目密码/Ruby zsteg，维持待解码。
- **装 PARI/gp**：specialcurve2 类复数乘法群 RSA 的 DLP 终局引擎。
  - 命令（managed venv 隔离，不污染用户环境）：
    `conda install -c conda-forge pari` 或系统装 `gp` 后加入 PATH。
  - 装后重跑 `skills/crypto_complex_mult_group.run()` 应直接出 flag（已验证前面步骤分解 n 成功，只差 DLP）。
- **装隐写工具链**：`pip install stegano stepic opencv-python-headless`（或系统 zsteg），覆盖 vnctf_flag 类 LSB 非标准变体。
- **补数据集真值**：vnctf_flag 的 `flag` 字段回填（用 stegsolve/专用工具解出后写入 `data/questions_real/misc/real_misc_vnctf_flag.json`）。

### 1.4 国产题型专项路由（差异化拉分，开源竞品 100% 卡壳）
- presolve 已有 `crypto_complex_mult_group` 路；需补：`web_source_audit`（CMS 后门/CVE，已存在）、国产 RSA 变种（低指数/共模/小素数/自定义 padding）、中文 SSTI 过滤绕过、zip 伪加密、流量自定义字段。
- 这些题型 verialabs/开源项目**原生不覆盖**，是 vs 开源标杆的真实护城河。

## §2 训练层（把 LLM 真推理从 0 拉起）

> 核心矛盾：13/15 全是 presolve 静态直出，main_agent_llm 真推理贡献 0/2。presolve 是"死知识"，对手也能堆；**LLM 在未知题上的泛化推理**才是分水岭，也是当前瘸腿点。

### 2.1 死磕残留 2 题（已定位根因）
- specialcurve2：装 PARI 后验证 presolve 直出 → 但这仍不算"LLM 真推理"。要测**LLM 在缺 presolve 时能否解**——临时禁用 `_try_complex_mult_group` 跑 main_agent，看重型模型（deepseek-reasoner）能否从附件脚本推理出复数群 DLP 思路。
- vnctf_flag：补真值 + 隐写工具后，测 LLM 能否自主选对隐写工具并解出（而非 presolve 直出）。

### 2.2 刻意练习"无 presolve 兜底"集
- 从真题集抽 5–8 道 presolve 未覆盖的题，强制 main_agent 裸推理，记录：工具链缺失 / 提示词退化 / 模型上限 三类失败，针对性补。
- 参考 `专属针对性训练方案.md` 五大专项：题型适配、故障闭环、限流成本、人机协同、答辩工程化。

### 2.3 多模型分级路由实战化
- 当前 baidu/qwen 双源已接但真推理 0——说明不是"没接模型"，是"主 Agent 在难题上没真正推理"。
- 把重型模型在 watchdog 升级链路里**真正用起来**：presolve 失败 → 轻量模型首解 → 连续失败升级 deepseek-reasoner/qwen-max-thinking → 仍失败触发监督者止损换题（已有 `_try_complex_mult_group` 同款升级逻辑可复用）。
