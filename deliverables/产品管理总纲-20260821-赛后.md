## 五、管理机制（防再乱 · 六条铁则）

1. **SSOT 原则**：本总纲是唯一权威。任何新行动项先回写本文件再执行；每周一（或每工作会话）对账：`git status` + backlog 状态。
2. **改码纪律**：改码必重启进程；**e2e 验证是唯一判据**（诊断=修复、写文件=生效 两个等号都不成立——初赛最痛教训）；决赛前 48h 只读冻结。
3. **git 纪律**：pre-commit hook 拦截 `ak_/sk-` 模式；提交前 `git status` 必须干净；commit 规范 `type(域): 描述`。
4. **多会话协作（CTDE：规范层 + 执法层）**：规范层 = `协同协议/多智能体协同协议-20260822.md`（开工登记 `.workbuddy/locks/`、文件域隔离、核心文件非协调者只读、TASK_BOARD 认领、门禁为神）；**执法层 = `scripts/_lease.py` + pre-commit scope 门禁（机器拦截，不靠自觉）**——会话 `acquire` 租约（scope=认领域，TTL 30min，提交即自动续租），越界/他人存活租约的 commit 直接被 hook 拒绝；挂死会话的 stale 租约可 `--force --reason` 接管（留痕）。两层冲突以执法层为准。历史教训：初赛 SyntaxError 即两会话同时改同一文件（2026-08-22 同日 09:20"单写者"口号立完即被并行会话打破——口号无执法，协议+hook 才有）。
5. **验收门禁**：每个 P0 项有明确验收标准（见 Backlog）；关闭项必须引用 commit/证据；验收人 = Gu。
6. **汇报节奏**：每工作会话结束写 `.workbuddy/memory/YYYY-MM-DD.md`；W1-W5 每周末在总纲更新 backlog 状态并定下周验收人。
