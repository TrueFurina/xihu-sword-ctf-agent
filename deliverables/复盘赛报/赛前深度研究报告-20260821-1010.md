## 三、赛制与规则深度研究（官方情报交叉验证）

### 3.1 官方规则要点（来源：杭州政府网/中新网/阿里云高校计划 2026-07-13 公告）

- **赛制**：首次引入 AI Agent 解题夺旗——题量远超人工上限，**只开放 API，无网页答题入口**
- **赛程**：报名 7/13→8/10；测试赛 8/18-19；**初赛 8/21 14:00-17:00（3h）**；晋级名单 8/31 前；决赛 9 月底前
- **晋级**：初赛综合成绩前 **12 名**进决赛
- **决赛**：现场系统演示 + **专家组代码审查与技术问答**——工程可复现性、诚实水位是硬门槛
- **奖励**：一等奖 1 / 二等奖 2 / 三等奖 3 / 优胜奖 6，总奖金池超 30 万

### 3.2 评分机制（选手群情报 + API 文档交叉验证）

- **递减积分制**：每被解出一人扣 1%，**最低 80%**；一血 = 100% 分
- **含义**：**开局密度 >> 收尾攻坚**。前 12 名拼的是 0-30min 的一血/EASY 早解积分密度，HARD 在 120min 后性价比趋近 0
- **平台字段**：difficulty（EASY/MEDIUM/HARD/VERY_EASY）+ score + isNeedInit + endpoints，P0-2 三点联动已打通

### 3.3 反作弊红线（选手群核心情报，必须合规）

1. **解题报告必须与网络流量日志、平台日志吻合**——API 调用全可追溯，只写答案不实际调 API = 取消资格
2. **白名单模型**：测试赛强制白名单，正式赛可能放宽但需提前适配（我们 ENFORCE_WHITELIST=1 已合规）
3. **网关 URL**：支持 /v1 和 /v1/chat/completions 两种格式（技术实现已验证）
4. 公益赛事不收任何费用，私信收费=诈骗（与我们无关，仅确认合规底线）

### 4.1 选手群生态（1,914 条消息分析）

- 选手普遍**经济有限但技术热情高**：免费额度（阿里 300 元/年）、百炼注册赠送是主流

- 部分选手会考虑"手工做题"绕过——**我们有确定性链预扫，反而更快**

| 维度 | 我们 | 标杆 | 差距 |

## 五、赛前可修缺口清单（13:30 前完成，按优先级）

### 🔴 P0-1：3 个 env 未固化到注册表（实测确认！）

抢分方案第四节要求 setx 固化，但实测 `_env_or_registry()` 返回空：

```
CTF_AGENT_RACE_PROFILE    = <未设置>   ← 应为 full
CTF_AGENT_MAX_CONCURRENCY = <未设置>   ← 应为 2
CTF_AGENT_PER_Q_WALLCLOCK = <未设置>   ← 应为 300
```

**影响**：进程启动时 `_race_profile()` 回落 full（默认），并发回落默认 8（**超 HTTP 槽 4 → 排队吃墙钟！**）。必须显式固化。

**修复命令**（13:30 前，新终端生效，start_race.bat 也会读到）：
```bash
setx CTF_AGENT_RACE_PROFILE full
setx CTF_AGENT_MAX_CONCURRENCY 2
setx CTF_AGENT_PER_Q_WALLCLOCK 300
```

### 🔴 P0-2：watcher 未接入竞速档位（实测确认）

`scripts/_scan_firstblood.py:90,159` 的 `watch()` 直调 `build_race_solver(use_mock=False)` **无参**——不读 `CTF_AGENT_RACE_PROFILE`，watcher 默认走 12 路全模型 → 429 风险 + 成本翻倍。

**修复**（改 2 处，30 秒）：
```python
solver = build_race_solver(use_mock=False, **_race_profile())  # 需 import 或按 _race_start 同款逻辑
```

### 🟠 P1-3：goal_log.jsonl 混入测试数据（实测确认）

最新 3 条日志均为 `task_id: "supervise_test"`（09:51 测试残留）——开赛前 **必须清空** goal_log.jsonl + solve_progress.json，否则：
1. 监控对账（S2/S3）会误判「已解出」→ 提交对账 delta 异常
2. 赛后报告混入假数据，**违反流量日志一致性红线**

**修复**：
```bash
rm data/results/goal_log.jsonl
python -c "import json,time;json.dump({'solved':{},'updated_at':time.time()},open('data/results/solve_progress.json','w'))"
```

### 🟡 P2-4（可选，有余力再做）

- `llm/client.py:47` 信号量支持 env（`CTF_AGENT_HTTP_CONCURRENCY`）→ 放开 8 提升吞吐（改完必须压测 429）

## 六、赛中作战决策树（3h 实时版）

```
14:00:00  start_race.bat 启动（--compete 自动：扫全量→难度排序→top2 模板直出→转轮询）
14:00-14:03  确认矩阵档位（monitor S5 打印实际生效 profile=full）
14:03-14:30  一血黄金窗口：轮询 burst=3s；每 10min 跑 monitor_race.sh
            ├─ 429 3-9/10min → setx RACE_PROFILE medium + 并发3 + 重启
            ├─ 429 ≥10/10min → setx RACE_PROFILE minimal + 并发4 + 重启
            └─ 402 新增 → deepseek 欠费告警（主源 qwen 不受影响，勿重试）
14:30-16:00  MEDIUM 攻坚：单题墙钟 300s；失败不重试；"差一点"的题手动单题重跑
16:00        暂停启动新 HARD；对账 submitted_flags vs goal_log（delta 应≈0）
16:30        只抢 EASY/确定性链题；HARD 一律跳过
16:45        python scripts/_emergency.py --finish 保底报告
17:00        Ctrl+C → --compete 自动生成报告 → 核对 submitted_flags.json
```

**赛中纪律（铁律）**：
1. 只认平台 accepted / validated，不信 Agent 自报"解出"
2. 恋战即弃：墙钟止损优先，失败题不重试
3. 60s LLM 读超时若频发 → `setx CTF_AGENT_LLM_TIMEOUT 90`（热修安全区，不必重启）
4. 全程 ENFORCE_WHITELIST=1 不关（合规红线）
