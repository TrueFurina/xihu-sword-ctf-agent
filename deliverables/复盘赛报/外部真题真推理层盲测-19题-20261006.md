## 三、成本与工程观察

- **成本极低**：两轮各仅 22,672 token（合计约 4.5 万 token，费用量级 < ¥0.2）。原因：L2 题多为"题面给足参数、1-2 步可解"的经典密码题（ezrsa/ezmult/simplelegendre 等），单题 200-1806 token 即完成。**这说明此前按 8 万/题估算的成本上限（¥2-3）严重高估**——真实瓶颈不是 token。
- **token 分布是能力信号**：解出的题普遍 ≤602 token；失败的题固定打满 1806 token 后放弃——失败形态是"想不出方向"，不是"钱不够"。

## 四、必须写明的局限（防止这份报告被过度引用）

1. **样本小**：19 题，单模型（deepseek-chat）单轮，无重复实验 → **无方差估计**。历史经验：同类口径两轮可差 10pp 以上（见 09-19 held-out 3/10 vs 4/10）。
2. **L2 是静态标签，不等于"难题"**：判定标准只有"附件里没有 flag 形态字符串"。像 ezrsa 这类题面参数完整、一步开根的题仍落在 L2，因此 42% 不可解读为"推理能力 42%"。
3. **题型偏斜**：L2 里没有 web/pwn（它们全在 L0），结论不能外推到 web/pwn 能力。
4. **本项目与出题方同源**：题来自本项目题库，虽剔除已训练题（未见题 1/10），但同一出题风格仍可能对自家引擎略有偏袒。

## 附：口径澄清 ——「LLM 自主解出数恒 0」的适用边界（2026-10-10）

`scripts/_kpi_canonical.py` 生成的台账写着：**「当前可验证的大模型自主解出数为 0」**，
依据是 `real_crypto_dnui_keyboard` 在两轮独立实测中均由 presolve 直出（78ms、tokens≈0）。

本项目的实测给出一个**必须限定的边界**：

| 口径 | dnui_keyboard 的解出方 | tokens |
|------|----------------------|--------|
| 默认（题首预扫开） | presolve 直出 | ≈0 |
| `CTF_AGENT_INTERNAL_PRESOLVE=off`（纯 LLM） | **main_agent_llm** | 602 |

两次判分互相独立（本项目 sha256 仲裁 + 对方 `judge_external_westlake.py`），结论一致。

**因此正确表述应为**：
> 在「默认配置 + held-out 2 题池」口径下，可验证的 LLM 自主解出数为 0；
> 关闭确定性层后，同一题可由模型在 602 token 内解出。

**不能说的**：「模型完全解不出 held-out 题」——那会把口径问题说成能力问题。
**也不能说的**：「模型已能解 held-out 题」——n=1（外部未见题仅 1 道），无统计意义。

口径纪律的通用形态：**任何"能力为 0 / 能力为 X%"的说法，必须同时写明配置口径与分母来源**，
否则同一道题在两个口径下会得到相反的结论。
