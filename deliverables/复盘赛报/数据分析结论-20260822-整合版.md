## 四、本次已落地的「极致修改」（安全、已验证）

1. **撕掉误导标签**：看板重分类为「真解出/真失败/本地缺口/伪成功」，并显式标记 `batch_solve_result.json` 为 MOCK。
2. **补 AES-ECB 确定性预解**：`run.py` 的 `fast_solve` 关键词表新增 `ecb/aes/aes-ecb`，使 crypto-004 类题型走 `crypto_ecb_block_attack` 确定性解，而非 LLM 瞎猜。
3. **回归验证**：`test_deterministic_chains.py` + `test_rsa_fallback.py` + `test_supervise_deadlock.py` 共 **14/14 全绿**，改动未破坏既有能力。

## 五、剩余真失败与赛中处置（非代码可解，需人）

- **crypto-004 / pwn-004 / pwn-005**：本地无附件数据→确定性链无米下锅；赛中平台提供附件后应可解，已接通 ECB 预解路径。
- **reverse-002**：卡死，需二进制逆向工具链/人工。
- **web（9 题 + web-004）**：本地无活靶无法测；赛中依赖平台活靶 + `web_toolkit` + 模板兜底，且 web-004 这类幻觉要靠 validated 拦截。

## 六、赛中纪律（铁律）

1. **只看平台 accepted**，任何「solved」以 `validated=True` 为准，不信自报、不信 Mock。
2. crypto/pwn 放手自动跑（确定性链已验证）；reverse/web 交活靶+人工。
3. 开赛先用 1–2 道 web 实测真实能力，确认活靶通路。
4. 真实水位以《攻坚实录》**89%(8/9)** 为准（模型+确定性链组合口径；独立彩排口径 33%）。

## 七、真实水位一句话

**代码层是诚实的**（校验拦得住幻觉），问题在**数据层假象**（Mock 假解 + 4 条伪成功 +「死题」误标）。撕掉假象后：基本盘 21 题真解出可靠，5 处真失败要靠赛中活靶+人工兜底，整体以 89% 真实水位为对外口径。

## 五、关键结论（数据支撑）

1. **测试赛 7/7 是假信号**：corpus 题与本地语料同源，预扫秒解，不代表真题能力。**"预扫秒解"能力在正式赛无任何输出。**
2. **数据链路 = 生命线**：附件/靶机/题面三要素缺一，LLM 输入即空，再强的推理能力也等于零。preflight 验证必须进开赛铁律。
3. **熔断机制缺失致命**：坏 provider 持续空转数十分钟（16:48-17:00），烧掉的是比赛最后的黄金时间。
4. **能力缺口是 0 解出的最终原因**：赛后修好链路后仍须面对"agent 只会解自己的题"——32 道真题 + 80+ 附件是决赛翻盘的唯一弹药。
5. **幻觉防线证明有效**：LLM 报 81 个 flag 全部被 flag_checker 拦截、validated=0——"只信 validated/accepted"的纪律是数据验证过的正确设计。
6. **真库攻坚 89% 的启示**：确定性攻击链（不赌 LLM 写代码）是真库水位从 28.6%→89% 的杠杆。决赛应把"确定性链优先"从 crypto 扩展到 misc 取证/大文件方向。
