## 二、根因链：为什么 0 解出（按时间线还原）

```
14:00 开赛 ── 故障①：平台 API 字段错配 → agent 拿不到附件/靶机/题面 → LLM 空输入空转
14:47 诊断 ── 0解出根因诊断报告完成（平台三层错配确认）
14:53 修复 ── 赛中热修附件下载（platform_downloads 开始有文件）
15:05-16:11 ── 多 session 并发跑 → 附件拿到了但依然 attempted≠solved
                （暴露故障③：题型判错 + 能力缺口 + 大文件慢）
16:48-17:00 ── 故障②：LLM 多源全部失效（千帆 401 / tokenhub 402 / deepseek 402）→ 最后 15 分钟纯空转
17:00 结束 ── 0 解出
```

### 故障① 平台 API 字段错配（14:00-14:47 主因）——已修复 ✅

三层错配，任何一层都足以饿死 agent：

| # | 错配 | 位置 | 后果 |
|---|---|---|---|
| 1 | `list_challenges` 只返回 5 字段 `{id,name,order,isOpen,hasSolved}`，代码假设 `has_attachment/has_instance` | `dasctf.py _parse_challenge`（旧版） | 两标志恒 False → 附件永不下载、`get_access` 永不调用 |
| 2 | `get_access` 解析 `host/ip/address/port/entrypoints[]`，真实字段是 `endpoints[].exposeIps[0]`（"ip:port"） | `dasctf.py get_access`（旧版） | 即使调用也取不到靶机地址 |
| 3 | solver 用 list 阶段的 `description`（空串）构造 Question，不二次调 `get_challenge` | `run.py` solver（旧版） | LLM 拿到空题面，监督裁决"无任何可操作输入" |

**日志实证**（10792 Rank-U）：
```
监督 LLM 裁决: action=give_up reason=题目缺少附件或靶机地址，模型已多次尝试但无任何可操作输入
```

**赛后修复**：`fdf1097 / 253d85a / 2b1b9b5 / 7aa601c` 已落地——solver 入口无条件 `get_challenge(ch.id)` 补全 detail、`_parse_challenge` 识别 attachment 嵌套对象与 endpoints、`get_access` 解析 `exposeIps`、附件下载复用平台鉴权头（403 修复）、靶机槽位 finally 回收。

### 故障② LLM 多源全部失效（16:48-17:00 灾难）——已修复 ✅

| 时间 | 现象 | 根因 |
|---|---|---|
| 15:30 前 | deepseek 402 余额耗尽 | 充值主源烧光，无熔断、无备用自动接管 |
| 16:48 起 | qwen3.7-plus/kimi-k2.6/doubao 全部打到 `qianfan.baidubce.com` → 401 invalid_iam_token | **父进程环境残留 `CTF_AGENT_LLM_BASE_URL=https://qianfan.baidubce.com`**，显式 provider 时仍被强制路由到千帆端点 |
| 16:54 | tokenhub deepseek-v4-pro 402 免费额度耗尽 | 竞速池源逐个死亡 |
| 16:57-17:02 | 全源 401/402，agent 空转刷日志 | 无熔断机制，坏 provider 持续空转数十分钟 |

**根因（赛后 cf595b2 定位）**：`_resolve_settings` 在显式 provider 时仍使用全局 `CTF_AGENT_LLM_BASE_URL` 覆盖 provider 默认端点。注册表 setx 残留的千帆端点把 moonshot/ark 请求全吸过去 → 401。

**赛后修复**：显式 provider 忽略全局 base_url；新增 401/402/403 连续 3 次熔断（`_PROVIDER_CIRCUITS`）；kimi/ark 强制 temperature=1；竞速档位默认改千帆主源（baidu+moonshot+ark）。

### 故障③ 题型分类错误 + 工具覆盖错配——部分修复 ⚠️

- `real_challenges.json` 中 **32 题里 24 题被归类为 misc（75%）**，真实分布应为 web/crypto/reverse/pwn 混合（10792 Rank-U 实为带靶机的动态题）
- 分类靠 title 前缀 + 附件名关键字猜测，list 阶段无附件信息 → 大量误判 → 选错工具包
- 后果：crypto 题走 misc 流程、web 动态题被当静态题空转
- **赛后已部分修复**（category 从 name 前缀提取 + 附件名辅助判型），但**未经正式赛真题回归验证**——决赛前必须用 `data/race_details/` 33 个 detail JSON 全量复测分类正确率

### 故障④ 能力缺口：本地语料 ≠ 正式赛真题——未解决 ❗（决赛最大风险）

**这不是 bug，是能力问题，也是 0 解出的最终原因**（数据链路修好后依然解不出）：

| 对照 | 结果 |
|---|---|
| 本地语料 35/70 | 多为自出题 + 测试赛 corpus（EASY/MEDIUM），预扫秒解 |
| 正式赛 32 题 | 全新真题：PKCS#1 v1.5（CRYPTO-01）、e=65536（CRYPTO-02）、449MB zip、16MB pcapng、exe/apk、靶机交互（Rank-U） |
| 手动攻坚实录 | CRYPTO-01 手动解到 PDF 无 flag、CRYPTO-02 数学复杂、WEB-01 靶机 HTTP 000、大文件分析慢 → **人工也未能解出** |

关键差距：
1. **无 PKCS#1 v1.5 / 大指数 e=2^16 的确定性 skill**（skill 库以 RSA 小 e/费马/Wiener 为主）
2. **大文件分析无提速手段**（449MB zip 解压即数分钟，16MB pcapng 无快速过滤）
3. **WEB 靶机交互未打通**（HTTP/HTTPS 000 连接失败，可能靶机槽位/代理问题）
4. **技能覆盖面 25+ skill 偏 crypto/web 模板，正式赛 misc 大文件/取证类几乎空白**
