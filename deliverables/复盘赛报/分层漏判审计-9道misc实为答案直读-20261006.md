## 二、根因（分层脚本的候选提取有形态盲区）

`scripts/_stratify_external_benchmark.py:36`：

```python
FLAG_RE = re.compile(rb"[A-Za-z0-9_]{1,20}\{[^}\s]{4,120}\}")
```

该正则**要求答案必须有 `xxx{...}` 花括号包裹**。而上述 9 题的答案是裸明文
（`1` / `80` / `Cisc0` / `cisco123` / 32 位 hex …），**无花括号 → 压根没进候选集**
→ 没被判 `L0_direct_read` → 全部落到 `L2_pure_reasoning`。

**这是第二次踩同类坑**：2026-10-05 曾实锤外部池 21/40 题附件是「符号链接路径文本」（`_attachment_integrity_audit.py`）。
那次是「附件不是真文件」，这次是「附件是真文件但内容就是答案」——**同源变体：静态分层只看形态，不看语义。**

## 三、修复（已改，零误判设计）

在 `stratify()` 的附件扫描循环内增加裸答案候选：

```python
# 仅对 <=4KB 附件做（真答案文件都是几十字节），不对 pcap/二进制全文做无意义比对；
# 仍走 matches_truth 精确摘要比对，且未命中不计入 cand_count（不影响 L1/L2 判定）。
if len(raw) <= 4096:
    for c in [raw.strip()] + [ln.strip() for ln in raw.splitlines()]:
        if c and matches_truth(c, truth):
            direct_hit = True
            cand_count += 1
            break
```

设计要点（防误伤）：
- 只对 **≤4KB** 附件做，避免对大 pcap/二进制做无意义全量比对；
- 仍走 `matches_truth` **精确摘要比对**——不是"看起来像答案"，是 sha256 严格相等；
- 未命中**不计入** `cand_count`，因此不会把 L2 误抬成 L1。

## 五、被推翻的判断（重要）

原判断：
> 「11 道失败里 9 道是 misc（流量重构 / 小剑系列），需要专用工具链（pcap 解析、流量重组），
> **补工具链的边际收益远高于换模型**，那是从 10% 往上走的最短路径。」

**证伪**：
1. 这 9 题**没有 pcap 可解析**——真实流量包从未下载，附件里只有答案 txt；
2. 它们的 0 分是**空输入的必然 0**（真输入缺失），跟模型推理、跟工具链都无关；
3. 补 pcap 工具链**边际收益为零**——没有输入数据，工具无用武之地。

**正确归因**：这 9 题应标 `NO_INPUT`（载荷不可得），**从任何能力分母中剔除**，
而不是计入 0/N（否则分母虚高 → 系统性低估能力）。
