## 一、为什么是"分层诚实"？

AI 解题项目的解出率有三个完全不同的口径，混在一起就是自欺：

| 口径 | 含义 | 可信度 |
|------|------|--------|
| 温室水位 | 本地题库 + 已知答案 + Mock 环境 | ❌ 不可信（过拟合） |
| 独立水位 | 纯 LLM + 独立答案校验（无题解污染） | 🟡 可信但局限 |
| 实战水位 | 真实平台 + 真实题 + 真实提交 accepted | ✅ 唯一权威 |

本报告三层全给，但**只有第三层能写进战绩**。

## 四、10719 事件（全场唯一的"赢"与"输"）

**它证明了什么**：数学引擎 + LLM 竞速 + 墙钟兜底**全链路能解出真实题**——能力底子存在。

**它暴露了什么**：`dasctf._request` 任何失败返回 None → `submit_flag` 笼统成"提交无响应" → poller 熔断器计入连续失败 → 连续 5 次 → **正确 flag 被静默丢弃**。

> 一句总结：**这套系统连"把赢下来的东西保住"的能力都没有——因为"提交成功"这一步，从来没有被当成需要验证的对象，只被当成"应该成功"的默认值。**（此条已修复，见 §五）

## 八、答辩 Q&A 预案（被追问 0 解出时）

**Q：你们正式赛 0 解出，凭什么说能力行？**
A：0 分根因是平台 API 字段错配（数据拿不到），不是解题能力。赛后用真实环境重放 12 道正式赛真题，11 道解出；10719 全链路解出但被提交熔断吞掉。修复后 e2e 验证脚本可复现数据链路。

**Q：89% 水位是真的吗？**
A：那是温室口径（历史真题 + 答案在库），已下架禁止引用。我们的对外口径只有两个：独立水位 33%、实战水位 0%（正式赛）→ 11/12（赛后重放）。

**Q：确定性 skill 是不是硬编码作弊？**
A：不是。skill 是攻击模板 + 参数槽，由 LLM 选题型、填参数、判结果。确定性部分只负责计算（RSA 分解、zip 爆破），推理决策仍由 LLM 完成——这是人机分工。

**Q：怎么证明不是运气？**
A：测试门禁 164 项全绿可复现 + e2e 验证脚本 + 32 道真题 80+ 附件全量保留，任何数字可重跑。
