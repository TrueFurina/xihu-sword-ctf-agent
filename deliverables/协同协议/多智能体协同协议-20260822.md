# 多智能体协同协议（西湖论剑 CTF-Agent · 2026-08-22）

> **⚠️ 2026-08-23 诚实降格（G0）**：本文档原名「CTDE 协同协议」，「CTDE」系 MARL 训练范式术语（需 critic+价值函数+回合奖励），本项目无此三者，属术语错用，已删除。本协议实质是「多会话写租约协议」。

> **⚠️ 2026-08-22 增补（执法层）**：本协议为**规范层**（给会话/人读）。
> **执法层** = `ctf_agent/scripts/_lease.py` + pre-commit scope 门禁（commit 时机器拦截）：
> 会话 `acquire` 租约（scope=本文件域隔离表认领的域，TTL 30min，提交即自动续租），
> 越界/他人存活租约的 commit 直接被拒；挂死会话的 stale 租约 `--force --reason` 接管留痕。
> 两层冲突时**以执法层为准**（机器拦的 > 自觉的）。详见 `ctf_agent/AGENTS.md` 二次修订段。

> **背景**：初赛 0/62 根因之一是"多会话无锁并发"（改码不重启、互相覆盖、门禁被删数据打红）。
> 赛后仍有大量并发会话在跑。本协议把多智能体协作从"无锁乱撞"改为**租约范式**：
> **协调者** = 单一协调者定任务分解 / 验收 / 冲突仲裁；
> **执行会话** = 各会话在认领的文件域内执行，写前持租约。
> ✅ **执法层现状（2026-08-23 G1 已落地）**：`_lease.py` 为**目录级多写者租约**——不相交 scope 可并行（`scopes_conflict` 相交判定 + 双时间戳 + `lease_version` fencing），不再是一次仅一个会话可写的全局单写者锁。
>
> **阅读对象**：所有 AI 会话 / 人工会话，开工前必读。
> **硬规则**：违反任意一条 = 重演 0 分。不遵守的会话不是"帮手"，是"事故源"。

## 二、硬规则（每条对应真实事故）

### R1. 开工必登记（防"不知道谁在写什么"）
1. 开工前读本协议 + `TASK_BOARD.md`（见下）。
2. **写文件前**：以 `_lease.py` **租约为唯一执法锁**（`acquire --scope`；commit 时机器拦越界/他人存活租约）。
   - ~~`.workbuddy/locks/` 文件锁~~ **已废弃（2026-08-23 锐评 P1-1）**：双锁体系职责不清——文件锁无任何执法、与租约互不感知，仅保留为"工作区可见登记"辅助层，**不作准入依据**。
3. 一个会话**同时最多持 1 个租约**（scope 可含多个文件域；防囤积/防 broad scope 退化成半全局锁堵路）。
4. **收工仪式（2026-08-24 闸4）**：会话停止前必须 `python ctf_agent/scripts/_closeout.py --check` **零在飞改动**（有残留 → 确认归属 → 提交或协调者裁决），再 `_lease.py release` 释放租约。**改了不提交就走 = 埋雷**（纲领 §4「在飞改动禁令」）。

### R2. 文件域隔离（防互相覆盖）
- 每个会话只能写自己任务板登记的路径。
- **核心文件全域只读**（对非协调者）：`run.py / config.py / core/ / ctfplatform/ / llm/ / tools/ / tests/ / setup.sh / pytest.ini / AGENTS.md / deliverables/产品管理总纲*`。
  - ⚠️ **2026-08-23 锐评 P1-2 如实声明**：本行为**君子协定，执法层暂不拦截**——`_lease.py` 只认 scope 路径、不认角色，会话 acquire 覆盖核心域的租约即可提交（历史实证：0dcf348/4b95160/2528452 均为非协调者改核心成功）。要真执法需在 `_lease.py` 加角色-路径黑名单（未落地）。**别把本条约当机器门禁**。
- 允许自由写：`data/`（新解压目录）、`skills/`（新 skill 文件，命名唯一）、`solutions/`、`scripts/analysis/`、`logs/`。

### R3. 门禁是神（防"声称绿实则红"）
1. 任何代码改动后：`.venv/Scripts/python.exe -m pytest tests/ -q -m "not slow"` 必须绿。
2. **不许**："py_compile 过了就算过了"、"单文件测试过了就算过了"——全量门禁说了算。
3. 测试红 = 先 `git status` 看是不是别的会话改了 D/M（**禁止 `git checkout --` 无条件恢复**——会销毁别人未提交的在飞工作，2026-08-23 锐评 P0-3 明令删除）；定位改动归属 → **协调者裁决 → 定向处理**。

### R4. 改码必重启 + 小步提交（防"文件改了进程没生效"）
- 赛时改码必须重启进程；commit 一个意图一条，message 写根因+验证。

### R5. 数据只增不删（防"删了门禁依赖"）
- `data/attachments/` 下**禁止删除**（测试引用）。解压产物只允许建新目录，不许删源 zip。
- 大文件清理：移出 git 跟踪（`git rm --cached`）+ 加 `.gitignore`，**不物理删除本地文件**。

## 四、冲突仲裁（协调者裁决）

| 冲突 | 处理 |
|------|------|
| 两会话要写同一文件 | 锁先到者得；协调者看 TASK_BOARD 判归属 |
| 门禁突然红 | 先 `git status` 看有没有别人的 D/M；恢复数据优先，不急着改代码 |
| main 分支有人直接提交 | 协调者仲裁后定向处理（**禁止无条件 checkout 回退**——会丢在飞工作，锐评 P0-3），责任人认领违规 |
| 协议与 SSOT（产品管理总纲）冲突 | 以 SSOT 为准，回写本协议 |

## 六、一句话

> **并发不可怕，无锁并发才可怕。本协议的全部秘密就三条：开工登记、文件隔离、门禁为神。**
> 写文件前先想三秒：这个文件有没有可能正在被别人写？有——换文件；没有——上锁再写。
