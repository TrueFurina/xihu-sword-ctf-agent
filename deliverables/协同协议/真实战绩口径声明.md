# 真实战绩口径声明（单一可信源）

> 配套：原则层 `多智能体协同准则纲领.md` §5（诚实产出 RDD 红线） · 规范层 `CTDE协同协议` · 执法层 `AGENTS.md` §13–§15（文档预算红线 / GO-NO-GO 红线）。
> 本文件钉死唯一口径，所有复盘 / 实证 / 锐评 / 展示文档**必须引用本声明**，不得各自表述、不得软化措辞。

## 一、唯一判据

**DASCTF 正式比赛环境（初赛 / 决赛）中，某题 flag 被平台返回 `accepted` = 真解出。除此以外的任何「解出 / 水位 / 解出率 / 通过率 / 拿下 / 攻破」表述，均非竞赛战绩。**

## 二、本项目真实战绩（钉死，不可改写）

- 第 20 届西湖论剑·中国杭州网络安全技能大赛 **初赛：真实平台 accepted = 0 解出、0 有效提交**。
- 根因：平台 token 返回 `40403` 无权操作、测试赛已关、当前无开放赛事；初赛 64 题 0 解出（平台 accepted = 0）。
- **竞赛得分 = 0**。此数字与任何「本地分析命中 flag」无关，不得用后者抵消或暗示「接近得分」。

## 三、口径红线（违反 = RDD 自循环，按 AGENTS.md §13 拦截）

1. 凡写「解出数提升 / 水位提升 / 真实水位 X% / 将功补过 / 真实水位」类表述，**必须**附该题「平台 accepted」记录（题号 + flag + 平台回执）。无记录禁止写。
2. 「本地离线刷题库命中」「沙盒实测 + 人工独立验证」「自出题演练」等**只代表工程能力验证**，不代表竞赛战绩；文档须显式标注「非平台 accepted」。
3. 「1/32」「14/14」「89%」等数字若未同时标注**来源场次**与**是否平台 accepted**，一律视为口径缺失，答辩 / 对外材料禁用。
4. 离线真题复盘单独归档（`data/results/_archive_离线刷题复盘-20260822.md`），不得与「项目解出数」混用进战报口径。

## 四、工程质量与解题战绩严格分离

- 工程质量（测试门禁 + 租约执法 + 双门禁 hook + 离线演练体系 + 协同准则纲领）**真实达标**，是可交付资产。
- 但**工程质量 ≠ 解题战绩**。展示工程治理能力时，不得暗示「因此题解得多」或「工程完备即接近得分」。

## 五、引用方式

任何对外 / 答辩 / 展示文档，在出现战绩相关表述的页面顶部统一加如下横幅（或等价中文）：

> ⚠️ **竞赛真实战绩声明**：本项目初赛真实平台 accepted = 0 解出、0 有效提交。本文所述「解出 / 水位」若无「平台 accepted」记录，均指本地离线分析或沙盒实测，非竞赛战绩。统一口径见本声明。
