# 多智能体协同准则纲领（CTF-Agent 项目）

> **原则层（本文件）** · 配套：**规范层** `多智能体协同协议-20260822.md` · **执法层** `scripts/_lease.py` + `.git/hooks/pre-commit`
>
> 本纲领定「为什么 / 什么不可妥协」；协议定「怎么执行」；执法层定「机器怎么拦」。
> 三层之中，只有执法层是法律，纲领与协议是约定——约定靠执法层落地，不靠自觉。

---

## 0. 缘起：本纲领为何存在

本项目在初赛的真实战绩是 **0 解出、0 有效提交**。复盘确认根因不是「题太难」，而是
**多会话无锁并发 + 文档通胀（RDD）**：

- 多个 AI 会话同时改同一批核心文件，互相踩、互相覆盖；
- 会话退出前不提交、不回退，留下「在飞改动」（M 文件），下个会话接管时如拆炸弹；
- 复盘文档把「本地离线解出」写成「真题解出」，把「应当可以」写成「已验证」，文档体量 > 真实产出。

本纲领把以上教训固化为**不可妥协的协同纪律**。它面向所有会动这个项目文件的 AI 会话，
无论自称「后勤」「协调者」还是「某成员」。

---

## 1. 机器强制优先于自觉

- AGENTS.md / 本纲领里的条款，**不是法律，是文档**。真正的法律是 `scripts/_lease.py` 与
  `.git/hooks/pre-commit`——它们机器拦截，不靠谁「记得看规矩」。
- 任何「应该遵守」的纪律，若不能被 hook / 脚本强制，就不算数；能强制的优先强制。
- 推论：**改文档补充规矩的同时，必须同步补强制手段**，否则只是新增一段没人看的字。

## 2. 身份显式，匿名不可写

- 每个会话启动第一件事：`export CT_AGENT_SESSION=<全局唯一标识>`。
- 无 `CT_AGENT_SESSION` 且无单人模式 → 提交被 hook 直接拒绝。
- 单人调试且**确认无并行会话**时，可用 `CT_AGENT_SINGLE=1` 放行；这是临时逃生口，
  **严禁长期用作绕过**——那正是初赛「多会话无锁」的根因，hook 已在该分支打印警告。
- 协调者身份固定为 **Gu（沽思航）**，负责路由与收口，不代写专业产出。

## 3. 写前必持租约，scope 精确

- 对任意被跟踪（tracked）文件的修改，**提交前必须持有效租约，且 scope 覆盖该文件**。
- scope 取**目录级、互不相交**的分区（如 `tools/adapters/**`），不要声称 broad scope 偷懒。**（已落地 G1：`_lease.py` 为目录级多写者租约，不相交 scope 并行。）**
- 越界 / 他人租约 / 无租约 → pre-commit 拒绝；属自己 scope → 自动续租。
- 租约 TTL 30min，靠 heartbeat 续命；持锁者崩溃由 TTL 兜底，不死锁。

## 4. 在飞改动禁令（最关键的新规）

> 本项目最高频的事故不是「改错」，而是「**改了不提交就消失**」。

- **盲区**：租约只在 **commit 时**拦截，拦不住「改文件但不 commit」。因此新增铁律——
  **会话停止前（用户喊停 / 自然结束），工作树必须 clean，或改动已持租约提交。**
- 遗留的未提交 M 文件 = 炸弹。协调者发现「无主未提交改动」时，必须 triage，不得无视：
  1. **判连贯**：改动是否自洽、是否半成品；
  2. **扫密钥**：`scripts/_scan_secrets.py` 或等价 grep，确认无 `sk-*` / `ak_live_` / `DASCTF_TOKEN=`；
  3. **可测则测**：若有代码改动，跑 `pytest -m "not slow"` 确认不破坏；
  4. **接管或回退**：连贯 + 无危险 → 认领租约后 `git commit`（带 reason 说明接管自谁）；
     残缺 / 含危险物 → `git checkout -- <file>` 回退，不留匿名改动。
- 接管提交用 `acquire --force --reason "接管<session>在飞改动"`；只转移写权限，不丢他人已提交工作。

## 5. 诚实产出纪律（RDD 红线）

- **平台 accepted 是唯一解题判据。** 本地 / 离线解出（拉附件本地分析、从 PDF 还原 flag）
  一律标注「**非平台 accepted**」，禁止进战报、禁止当成绩、禁止写进答辩。
- 任何「通过 / 解出 / 可用」声明，**必须附可复核证据**：测试输出、实际命令、文件路径。
  **无证据 = 未做。** 禁止「应当可以 / 理论上 / 应该没问题」式声明。
- 文档增量必须对应真实产出。为显得有进展而造文档（文档通胀 > 真实产出）是红线。
- 本项目自检文档已钉死：「离线复盘严禁冒充战报」「任何复盘必须附真实平台 accepted 记录」。
  本纲领与之同效，冲突时以「平台 accepted 判据」为准。

## 6. 验证优先（verify-before-claim）

- 改了代码 → 跑测试再声称通过；
- 声称某 skill 可用 → 实际 `load()` + `run()` 验证，而非看注册表；
- 声称某平台 / API 接入 → 实际发一次请求看响应；
- 声称配置生效 → 实际打印生效快照核对，而非读代码推断。

## 7. 冲突与接管

- 租约 TTL 30min，提交自动续租；stale（持锁者崩溃 / 退出）→ 任意会话可 `--force` 接管。
- 接管**必须写 reason** 并记入日志（memory 日志 / commit message），禁止静默抢锁。
- 接管只转移「写权限归属」，不丢弃他人已提交的工作；已提交内容靠 git 历史保全。

## 8. 终止信号

- 用户「停 / 睡觉 / 别动」→ **立即收尾**（持租约提交，或 `git checkout` 回退），然后等待，
  **不自主续跑**。
- 并行会话退出前必须 broadcast 状态：写 memory 日志 + `release` 租约，让协调者能判定谁还活着、
  哪些是「在飞改动」需要接管。

## 9. 协调者职责（Gu）

- **路由**：简单任务直调成员，复杂任务走团队协作流程。
- **收口**：对无主在飞改动做接管裁决；对租约冲突做仲裁；对密钥 / 危险物做门禁。
- **不代写**：专业产出由对应成员完成，协调者只汇编结论、不替人写代码。
- **可接管**：停掉的会话若在飞改动连贯且无危险，协调者有权认领租约接管提交（须先 triage）。

## 10. 定义完成（DoD）

一次改动算「完成」当且仅当全部满足：

| # | 条件 | 验证方式 |
|---|------|----------|
| ① | 持有效租约 | `scripts/_lease.py status` |
| ② | scope 覆盖改动文件 | lease scope ⊇ 改动路径 |
| ③ | 密钥扫描过 | pre-commit ① 门禁通过 |
| ④ | 测试绿（代码改动） | `pytest -m "not slow"` 全绿 |
| ⑤ | 已提交 | `git log` 可见、工作树 clean |

缺任一条 = 未完成 = 不得声称「做完了」。

## 附：本纲领条目 ↔ 本项目真实病灶

| 纲领条目 | 对应的真实事故 |
|----------|----------------|
| §1 机器强制 | 初赛 0 分根因「多会话无锁并发」，仅靠 AGENTS.md 文字无效 |

| §4 在飞改动 | 并行会话退出留 3 个 M 适配器文件 / 5 个 bkcrack 文件未提交，下个会话接管如拆弹 |
| §5 诚实产出 | 日志「正式赛 10732(1/32)」实为本地离线解出，非平台 accepted；RDD 文档通胀 |
| §6 验证优先 | 48 个 skill 仅 12 个实证，36 个未上场却未标；「应当可以」式声明泛滥 |
| §7 冲突接管 | 协调锁残留文件卡死下一次 acquire（已加 fix，但仍是会话退出没收尾的症） |
| §8 终止信号 | 用户喊停后会话仍在后台改文件 |

> 本纲领不是理论，是本项目用 0 分换来的纪律。违反任一条，都是在重演初赛。
