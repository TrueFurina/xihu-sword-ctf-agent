## 2. G1 目录级多写者租约（核心，80% 价值）

### 2.1 数据结构改造

`coordination.json` 从单 session 改为多租约映射（JSON Schema 已在报告 §4.1 给出，此处给 Python 数据类视角）：

```python
# 旧（单写者）：{"session": "A", "scope": [...], "last_heartbeat": ..., "ttl_min": 30, ...}
# 新（多租约）：
{
  "version": 1,
  "identity": {
    "A": {"public_key": "ed25519:...", "key_id": "ab12cd34ef56ab12", "registered_at": "..."}
  },
  "leases": {
    "A": {"scope": ["agents/**"], "last_active": 1724330000, "last_commit": 1724330000,
           "ttl_min": 30, "key_id": "ab12cd34ef56ab12", "lease_version": 0},
    "B": {"scope": ["skills/**"], "last_active": 1724330010, "last_commit": 1724330010,
           "ttl_min": 30, "key_id": "cd34ef56ab12cd34", "lease_version": 0}
  }
}
```

关键字段语义：
- `last_active`（epoch 秒）：心跳续租时间，判定租约存活。
- `last_commit`（epoch 秒）：最后提交时间，用于归因与恢复点。
- `lease_version`（int）：fencing token 版本分量，每次 acquire/take_over 自增，拦截过期写。

### 2.2 接口签名改造（`_lease.py`）

保留外部命令面（`acquire/heartbeat/release/status/precommit`），改内部语义：

```python
# —— 改造点 1：acquire 增加 scope 相交判定 ——
def acquire(session, scopes, coor_path=COOR_DEFAULT, ttl_min=DEFAULT_TTL_MIN,
            force=False, reason="") -> bool:
    """改为：检查本 session 的 scopes 与其他存活租约的 scopes 是否相交；
    不相交→写入 leases[session]；相交→拒绝（除非 force 且对方 stale）。"""

# —— 改造点 2：新增 scope 相交判定 ——
def scopes_conflict(a_scopes: list, b_scopes: list) -> bool:
    """两两展开 glob 前缀，任一相同或互为前缀即冲突。"""

# —— 改造点 3：heartbeat 续租 last_active ——
def heartbeat(session, coor_path=COOR_DEFAULT) -> bool:
    """改为：更新 leases[session].last_active（而非旧 last_heartbeat）。"""

# —— 改造点 4：precommit 改用 leases map ——
def precommit(session, coor_path=COOR_DEFAULT) -> bool:
    """改为：owner==session 且 scope 相交校验 + 自动续 last_active；
    owner!=session 且双方 scope 不相交→放行（多写者并行）；相交→拒绝。
    无租约→fail-closed 拒绝（除非 CT_AGENT_SINGLE=1）。"""
```

### 2.3 核心伪代码

```python
def _expand_prefix(scope: str) -> set:
    """glob 展开为路径前缀集合。'agents/**' -> {'agents/'}；'a/b/**' -> {'a/b/'}。"""
    s = scope.rstrip('/').replace('**', '').rstrip('*')
    return {s + '/'} if s else {'/'}

def scopes_conflict(a, b):
    pa = {p for s in a for p in _expand_prefix(s)}
    pb = {p for s in b for p in _expand_prefix(s)}
    for x in pa:
        for y in pb:
            if x == y or x.startswith(y) or y.startswith(x):
                return True
    return False

def acquire(session, scopes, coor_path, ttl_min, force, reason):
    if not _acquire_lock(coor_path): return False
    try:
        doc = load(coor_path) or {"version": 1, "identity": {}, "leases": {}}
        for other, lease in doc["leases"].items():
            if other == session: continue
            if not _is_stale(lease) and scopes_conflict(scopes, lease["scope"]):
                if force and _is_stale(lease):
                    doc["leases"][other]  # take_over：lease_version+1，记 takeover_note
                    continue
                print(f"❌ scope 与 {other} 冲突（{lease['scope']}）")
                return False
        doc["leases"][session] = {
            "scope": list(scopes), "last_active": now(), "last_commit": now(),
            "ttl_min": ttl_min, "key_id": doc["identity"].get(session, {}).get("key_id", ""),
            "lease_version": 0}
        _write(coor_path, doc)
        return True
    finally:
        _release_lock(coor_path)

def precommit(session, coor_path):
    doc = load(coor_path)
    if not doc or not doc.get("leases"):
        # fail-closed：无租约默认拒绝
        print("❌ 无租约，多会话环境禁止无租约提交")
        return False
    files = _staged_files()
    my_lease = doc["leases"].get(session)
    if not my_lease:
        print("❌ 本会话无租约"); return False
    # owner 自己的 scope 越界拦截（保留旧逻辑）
    bad = [p for p in files if not path_in_scope(p, my_lease["scope"]) and not _exempt(p)]
    if bad:
        print("❌ 越出本会话 scope:"); [print("  " + p) for p in bad[:20]]
        return False
    my_lease["last_active"] = now()   # 提交即活跃心跳
    my_lease["last_commit"] = now()
    _write(coor_path, doc)
    return True
```

### 2.4 单元测试用例设计（`tests/test_lease_multiwriter.py`）

| # | 测试场景 | 断言 |
|---|---|---|
| T1 | A acquire `agents/**`，B acquire `skills/**` | 两者都成功（多写者并行） |
| T2 | A 持 `agents/**`，B acquire `agents/planner/**` | B 拒绝（scope 前缀包含） |
| T3 | A 持 `agents/**`，B acquire `data/**` | B 成功（不相交） |
| T4 | scope 相交判定边界：`a/**` vs `a/b/**` vs `ab/**` | `a/b/**` 冲突、`ab/**` 不冲突 |
| T5 | B 无租约提交 | precommit 拒绝（fail-closed） |
| T6 | B 持 `skills/**` 却提交 `agents/x.py` | 越界拒绝 |
| T7 | A 心跳 100 次无提交 | 租约不 stale（last_active 存活） |
| T8 | A 超过 ttl 无活跃 | 租约 stale，B 可 force 接管（lease_version+1） |
| T9 | A 被接管后迟到写（旧 lease_version） | fencing 拒绝 |
| T10 | 接管留痕 | takeover_note 记录接管自谁 + 原因 |

**关键断言（T1 是最重要的回归锚点）**：改造前 `acquire` 在 A 持租约时拒绝 B 的任意 scope；改造后 T1 必须通过——这是「单写者→多写者」的直接证据。

## 3. G2 身份 L1+L2（唯一 ID + 登记绑定）

**目标**：堵住「裸字符串撞名/误认」，不上 ECDSA（威胁模型是「犯错队友」非「恶意者」）。

**改动**：
1. `scripts/_sign.py`（新，~60 行）：`init_session(name)` 生成 `crypto-random` 唯一 id（格式 `<name>-<8位hex>`）+ 写入 `coordination.json.identity[name]`（先只存 `registered_at`，`public_key` 留空给 G5）。
2. pre-commit hook：`CT_AGENT_SESSION` 为空时，从 `identity` 表取唯一 id（而非裸 `git config`）。
3. 登记绑定：session id ↔ 本次 scope ↔ 启动时间，写入总账身份表。

**测试**：同名 session 冲突检测（两会话 `init_session("gu")` 生成不同 id）；无登记 session 提交被拒。

**目标**：把「写对不对」交给机器门禁，把「在飞改动」从靠自觉改为脚本强制。

**测试**：`_closeout.py --check` 在有 M 文件时 exit 1；干净时 exit 0。

## 5. G4 写耦合度聚类定 scope（可发表点）

**目标**：用 git 历史文件共现矩阵，自动划分 scope 簇（替代人工拍目录）。

**改动**：`scripts/_coupling_cluster.py`（新，~120 行）：

```python
# 1. 构建共现矩阵：遍历 git log --name-only，对同 commit 出现的文件对计数 C_ij
# 2. Jaccard 归一化：J_ij = C_ij / (C_i + C_j - C_ij)
# 3. 层次聚类（average-linkage），距离 = 1 - J_ij，阈值 θ=0.6 截断
# 4. 输出 scope 簇 -> 写回 coordination.json 的默认 scope 建议
```

**测试**：构造一个合成 git 历史（3 个强耦合文件簇），断言聚类正确分出 3 簇；阈值敏感性测试（θ=0.3/0.6/0.9 簇数单调性）。

**验收**：对 ctf_agent 真实 git 历史跑一次，输出 scope 建议，人工抽查「core/ 文件是否聚成一簇」「skills/ 是否按子域分开」。

## 6. G5 身份 L3 签名 + 归因权（解冻后，依赖 accepted 数据）

**目标**：ECDSA/Ed25519 commit 签名（映射 CCF 的 CA-less 身份）+ 双权重归因。

**改动**：
1. `_sign.py` 补 `generate_key()`（Ed25519）、`sign_commit()`（`git -S`）、`verify()`。
2. pre-commit 校验「签名会话 == 租约会话」。
3. `scripts/_credit.py`（新）：`merge_weight(session) = count(verified_commits)`；`attribution_weight(session) = Σ accepted × difficulty`（accepted 数 < N_min=30 时不参与 merge 决策）。

**前置条件**（硬门槛）：有平台 accepted 数据；项目解除冻结。

## 7. 依赖 DAG 与落地顺序

```
G0（文档诚实降格，冻结期内可做）
 └─ G1（_lease.py 单写者→目录级多写者租约，~150 行 + 10 测试）
     ├─ G2（唯一 ID + 登记，~60 行）
     ├─ G3（收尾脚本 + Reviewer 门禁，~80 行）
     └─ G4（写耦合度聚类，~120 行，可发表）
          └─ G5（签名 + 归因权，解冻后，依赖 accepted 数据）
```

- G1 是唯一「文档与现实不符」的真 bug 的根治，其余阶段按需。
- 单点风险最高的是 G1 的 scope 相交判定算法（漏拦=互踩重演、误拦=并行度损失），故 T2/T3/T4 边界测试必须先行。
