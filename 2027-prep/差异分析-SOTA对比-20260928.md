## 〇、一句话结论（诚实）

**本仓的「确定性优先」架构在 crypto/misc/rev 静态题上有效（KPI=14 全为 presolve/工具直出），但缺「持久交互会话 + planner/executor/reflect 闭环」，导致 presolve miss 后 LLM 路径无法真正与活环境交互——这正是 09-27 实测「扩池只换 0/N、LLM 真推理贡献=0/14」的结构性根因。**

补这层闭环，是让 LLM 从「0 贡献」走向「有贡献」的唯一杠杆；但它**必须跑在活环境（Linux/Docker）上**才能对 web/pwn 生效。Windows 上能先做的，是**抽象与脚手架**（不依赖活环境即可开发、单测）。

## 二、SOTA 有、本仓缺的能力（按杠杆排序）

### 🔴 P0 — 决定「LLM 能否有贡献」的结构性缺口

**G1. 持久交互会话 + 跨步记忆（scratchpad）**
- SOTA：EnIGMA 在活 shell 里跑命令，输出进会话历史，下一步接着上一状态走；CAI 有 `/history /compact /memory`。
- 本仓：presolve 是「一次性扇出 49 技能」，无状态积累；LLM 路径（core/main_agent.py）即使介入，也缺一个**跨步保留文件系统/命令输出状态**的会话对象。
- 后果：presolve miss 的题，LLM 看不到「我刚跑了什么、输出了什么」，只能凭题面静态猜 → 必然 0/N。
- **补法（¥0 可开发）**：抽象一个 `Session` 类（工作目录 + 命令历史 + 产物索引），先纯逻辑 + 单测，不接活环境。

**G2. planner → executor → auto-prompter 闭环**
- SOTA：D-CIPHER 显式「分解子任务(planner) → 执行(executor) → 失败自纠(auto-prompter)」。
- 本仓：supervisor 直接路由到分类 agent，无「先写计划、再执行、再反思修正」的显式循环。
- **补法（¥0 可开发）**：在 supervisor 下加 `PlannerAgent`（输出结构化 subtask list）+ `ReflectAgent`（读 executor 轨迹判失败并重规划）。这是把「0 贡献」变「有贡献」的核心。

### 🟠 P1 — 活环境工具抽象（需 Linux/Docker，归轨道 B）

**G3. 活环境工具集（gdb/pwntools/radare2/ghidra/浏览器）**
- 本仓 presolve adapter 全是**静态文件**导向；web/pwn 活的（服务/二进制交互）无任何工具。
- **补法**：轨道 B 开云后，定义统一 `Tool` 接口（run(cmd) / read(path) / interact(service)），G1 的 Session 直接复用。Windows 上只能先写接口契约 + mock。

**G4. MCP 标准工具协议**
- CAI 用 MCP 接外部工具。本仓 `tool_recipes`/`skill_manager` 是自有体系。
- **补法（可选，¥0）**：把现有 adapter 适配到 MCP server 形态，便于复用社区工具。非必须。
- ✅ **已落地 `ctf_agent/core/mcp_adapter.py`**（2026-09-28）：`MCPTool` / `MCPRegistry` + `tool_adapter_to_mcp()`——把现有 `ToolAdapter`（sync/async `run(params)->ToolOutput`）包装成 MCP `tools/list` schema 并支持 `tools/call` 分发，`initialize` 响应骨架齐备。不启 socket server（那需 mcp 包 / 轨道 B）。配套 `tests/test_mcp_adapter.py` **9 passed**。

### 🟡 P2 — 增强项（¥0，纯收益）

**G5. 会话压缩 / 记忆管理**
- ~~核实 `core/blackboard.py` 当前职责~~ ✅ **已完成（2026-09-28）**：blackboard = presolve 缓存 + 失败记录，**非**会话记忆 → 缺口真实。
- ✅ **已落地 `ctf_agent/core/memory.py`**：`SessionMemory` 类——规则式事实抽取（flag/path/error/cmd）+ `compact()` 会话压缩（保留最近 N + 命中关键事实的旧 step，CAI `/compact` 同类）+ `retrieve()` 关键词召回。LLM 语义压缩以可注入 `callable` 形式存在（默认 `None` 走规则式，零 token）。配套 `tests/test_memory.py` **11 passed**。

**G6. 模型路由广度**
- CAI 用 LiteLLM 接 300+ 模型。本仓 provider 窄。
- **补法（¥0）**：引入可扩展 `ModelRegistry`（`ctf_agent/core/model_registry.py`），统一 provider 白名单 + 模型登记表，并为 LiteLLM 预留后端注入点（`lite_llm_backend`，默认 None 零 token）。`from_config()` 从现有 `config.py` 加载真实登记表（失败开放，不阻断链路）。**已真实落地 + 7 passed（2026-09-28）**。

**G7. 提示注入防御对齐**
- 本仓已有 `anti_hallucination.py` / `flag_extract_guard.py`，与 CAI Guardrail 方向一致。**保持，不必追平 CAI 四层框架**（竞赛题面含对抗样本时本仓已有基础防护）。
