## 四、结构性空白识别（第二轮更新）

基于 20+ 项目的 11 维度矩阵分析，识别出以下 **真正空白**：

### 空白 1：「并发调度 + 预算熔断 + 错误归因」三合一 ✅ 已有 idea 覆盖
- 仅 hydra 有并发+预算（但单层、无错误归因）
- 仅 LLM-CTF-Solver 有僵局检测（但无并发、无预算分层）
- **西论 CTF-Agent 是唯一三合一方案** → IDEA-1 已覆盖

### 空白 2：「题型自适应路由 + 多模型分级调度」 ✅ 已有 idea 覆盖
- hydra 有 triage 分流（但无模型分级）
- LLM-CTF-Solver 有 challenge_classifier（但无路由调度）
- **西论 CTF-Agent 的 idea 将分类→路由→调度全链路整合** → IDEA-2 已覆盖

### 空白 3：「跨任务经验记忆 + 失败教训沉淀」 ⚠️ 部分覆盖
- SageCTF 有层级记忆（但依赖重型模型、无失败教训沉淀）
- CoRedteam 有 Consolidator（但仅预算耗尽后触发、仅 Web 题）
- **西论 CTF-Agent 的 idea 将触发频率和注入方式差异化** → IDEA-3 已覆盖

### 空白 4：「竞赛态势感知 + 动态资源分配」 🔴 未覆盖
- **没有任何项目**实现竞赛级别的态势感知：实时监控解题进度、对手动态、剩余时间
- 资源分配是静态的（hydra 的 cost-cap 是固定阈值），无动态调整
- **本项目 race_strategy.py 有先易后难基础，但缺态势感知** → 新 idea 机会

### 空白 5：「沙盒逃逸防护 + 命令注入防御」 ⚠️ 部分覆盖
- CoRedteam 有 AST 白名单（但仅限 Python/JS）
- 其他项目依赖 Docker（但 Docker 不防沙盒逃逸）
- **本项目有 subprocess 沙盒，缺 AST 前置校验** → 新 idea 机会

### 空白 6：「人类在环协作 + 渐进式自主」 🔴 未覆盖
- 所有项目要么全自主、要么需人类全程参与
- **没有任何项目**实现「信心阈值自主 + 低信心求助人类」的渐进式自主
- **本项目有 CTF_AGENT_ALLOW_HUMAN 环境变量基础** → 新 idea 机会

### 空白 7：「评测基准 + 可复现对比」 ⚠️ 部分覆盖
- 学术派有评测基准（InterCode、NYU Bench），但与实战脱节
- 实战派无标准化评测（各自自建题库）
- **本项目有 15 道真题评测，但缺标准化对比框架** → 新 idea 机会

### 空白 8：「工具输出专精过滤 + 上下文压缩」 🔴 未覆盖
- 所有项目对工具输出要么全量保留、要么简单截断
- **没有任何项目**按题型对工具输出做专精信息提取
- **本项目有 skills/ 55+ 工具，缺输出过滤** → 新 idea 机会

### 空白 9：「多源知识融合 + Writeup 检索增强」 🔴 未覆盖
- 所有项目仅依赖 LLM 内部知识
- **没有任何项目**在解题过程中检索历史 writeup/漏洞数据库
- **本项目有 presolve.py 静态分析基础** → 新 idea 机会

### 空白 10：「赛后复盘 + 自动化知识图谱」 🔴 未覆盖
- CoRedteam 的 Consolidator 是最接近的，但仅限运行时
- **没有任何项目**实现赛后自动构建解题知识图谱
- **本项目有 verify/error_classifier.py 基础** → 新 idea 机会
