# Experiment Plan: AI-CTF Agent 分层预算熔断 + 结构化错误归因

**Date**: 2026-08-27
**Target Venue**: 西湖论剑 AI-CTF 赛道
**Total Budget**: 9 道诚实真题 (kpi9 口径) × 4 种配置 = 36 次完整运行

## Experiment Blocks

### Block 1: 消融实验（Ablation Study）

**目标**: 证明每个组件的独立贡献

**配置矩阵**:

| 配置 | 并发 | 熔断 | 错误归因 | 监督裁决 |
|---|---|---|---|---|
| A: 基线 | ❌ 串行 | ❌ | ❌ | ❌ |
| B: +并发 | ✅ ≤8 | ❌ | ❌ | ❌ |
| C: +熔断 | ✅ ≤8 | ✅ 三级 | ❌ | ❌ |
| D: +归因 | ✅ ≤8 | ✅ 三级 | ✅ | ❌ |
| E: 全方案 | ✅ ≤8 | ✅ 三级 | ✅ | ✅ |

**指标**:
- 解出率 (solve_rate) = 解出题数 / 总题数
- Token 消耗 (total_tokens)
- 平均解题时间 (avg_time)
- 幻觉 flag 数量 (hallucinated_flags)
- 重试成功率 (retry_success_rate)

**运行方式**:
- 每种配置在 9 道诚实真题 (kpi9) 上跑 1 次
- 总计 5 × 9 = 45 次单题运行
- 预计总 Token: 按实测 Block3 基线 ~344k tokens/run × 2 配置 × 3 重复 ≈ 2.1M tokens（见 Measured Results）

### Block 2: 并发效率实验

**目标**: 找到最优并发数

**配置**:
| 并发数 | 预期效果 |
|---|---|
| 1 (串行) | 基线 |
| 4 | 2x 吞吐 |
| 8 | 4x 吞吐 |
| 12 | 可能资源竞争 |

**指标**: 吞吐量 (题/小时)、单题解出率、Token 消耗

### Block 3: 成本对比实验

**目标**: 量化三级熔断的成本节省效果

**配置**:
- 无熔断: 运行直到所有题完成或预算耗尽
- 有熔断: 三级熔断 + 降级调度

**指标**: Token 消耗对比、解出率对比、成本/解出率比

### Block 4: 错误归因效果实验

**目标**: 量化结构化错误归因对重试成功率的提升

**配置**:
- 无归因: 失败后直接重试（相同策略）
- 有归因: 失败后分析错误类型，定向修正策略

**指标**: 重试成功率、平均重试次数、解出率提升

---

## Run Order

1. **Block 1** (消融) — 最高优先级，证明核心贡献
2. **Block 2** (并发) — 找到最优参数
3. **Block 3** (成本) — 量化成本节省
4. **Block 4** (归因) — 量化归因效果

---

## Success Criteria

| 指标 | 目标 | 底线 |
|---|---|---|
| 解出率提升 | +20% vs 基线 | +10% |
| Token 节省 | 40% vs 无熔断 (a priori 目标，实测未达) | 20% (实测 18.7%，略低于底线 → 见 Measured Results) |
| 并发吞吐提升 | 3x vs 串行 | 2x |
| 重试成功率提升 | +30% vs 无归因 | +15% |

## Risk Mitigation

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| API 限流 | 实验耗时过长 | 分批运行，使用备用 API |
| 真题泄露 | 评测失真 | 使用本地评测体系，不提交到外部平台 |
| 并发资源竞争 | 解出率下降 | 从低并发开始，逐步增加 |
| Token 预算超限 | 实验中断 | 设置全局预算上限，优先完成 Block 1 |

## Measured Results (Claim 1 — 预算熔断, 2026-08-28)

> 由并行会话实跑完成，落盘 `ctf_agent/data/results/claim1/`（A1-A3 `_budget_off` 基线 + B1-B3 `_budget_on` 熔断，各 3 次重复，kpi9 诚实题集）。下列为对 6 份 `benchmark_report.json` 的真实提取，非估计。

### Block 3（成本对比）真实数据

| 组 | 配置 | 运行 | total_tokens (真实 LLM 用量) | solved/total |
|---|---|---|---|---|
| A_off | 无熔断 | A1 | 341,624 | 4/8 |
| A_off | 无熔断 | A2 | 345,637 | 4/8 |
| A_off | 无熔断 | A3 | 344,745 | 4/8 |
| B_on | 三级熔断 | B1 | 280,792 | 4/8 |
| B_on | 三级熔断 | B2 | 280,840 | 4/8 |
| B_on | 三级熔断 | B3 | 277,171 | 4/8 |

- **A_off 均值** = 344,002 tokens (sd 1,720；95%CI [342,055, 345,949])
- **B_on 均值** = 279,601 tokens (sd 1,718；95%CI [277,656, 281,546])
- **Token 节省 = 18.7%**（95%CI 近似 [17.7%, 19.7%]）
- **解出率**：A 与 B 均为 4/8，**delta = 0**（熔断不牺牲解出率）

### 与原 Success Criteria 的对账（防 flip-flop）

| 指标 | a priori 目标 | 底线 | 实测 | 判定 |
|---|---|---|---|---|
| Token 节省 | 40% | 20% | **18.7%** | ❌ 未达底线（差 1.3pp） |
| 解出率保持 | — | 不失分 | 4/8 = 4/8 | ✅ 完全保持 |

### 诚实结论

1. **"-40% Token" 假设被数据证伪**：真实效应约 19%，略低于 20% 底线。但这是**有基线、有 3 次重复、可复现**的真值，比原 proposal 的凭空目标更可信。
2. **真实、可发表的贡献 = "三级熔断在零解出率损失下节省 ~19% Token"**：对赛时 AICTF（预算/配额敏感）是直接可用的工程结论。
3. **关键局限（不隐瞒）**：`by_solved_by.main_agent_llm.solved = 0` → 9 题全由 presolve/工具链直出，**LLM 真推理贡献 0/9**。熔断省下的 token 主要是 presolve/工具调用链路的开销，而非"LLM 思考"。Claim 2/3（依赖 LLM 路径被触发）当前**不可证伪**，暂缓。
4. **基准口径**：token 为 `run.py` ContextVar 累计的真实 `usage.total_tokens`（仅无记录时回退长度估算），非估算值。
