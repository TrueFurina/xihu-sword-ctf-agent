## 二、核心问题诊断（分层，按对"解题数"的杀伤力排序）

### 问题 1（致命·能力层）：真实 LLM 决策质量 17%，且正式赛真题 0 解出
- 工具链很强（教学型真题 91.7% 覆盖），但 grep 赛时日志：确定性 fallback 标记（`[rsa_*`/`[morse*` 等）**真实 race 0 命中**——工具链与路由/调用没接上。
- 17% 是 questions_real 教学题水位，**正式赛 32 道新题的真实 LLM 水位从未测过**（平台 40403 测不了）。
- 结论：工具链强是"已装载的武器"，LLM 决策弱是"不会用武器"。解题数上不去，两头都得动。

### 问题 2（致命·题型错配）：正式赛 32 题 web 占 23 题（72%），全部是动态题（flag 在靶机）
- 赛后分类回归已确认：web 23 / crypto 2 / misc 3 / reverse 3 / pwn 1（30/32 HIGH 置信）。
- 23 个 web 源码包全量审计完毕：**全部官方原版源码（joomla/wordpress/drupal/cmsms/nginx…），0 明文 flag、0 后门**——静态审计只产出"版本→CVE"攻击面，**分数只能从靶机交互拿**。
- 赛时 10792 Rank-U 靶机 HTTP 000 未通；`web_target_interact` skill 已沉淀但**未经真题实测**。
- 结论：**web 靶机交互是解题数的上限决定者**。打不通 = 静态可解约 9 题封顶；打通 = 上限 32 题。

### 问题 3（严重·流程）：git 证据链断裂 + 8 个核心文件在飞
- 产品管理总纲引用的 30+ commit（cf595b2/fdf1097/3449e16…）已不在 git 历史中，只剩重建基线 2 条。**答辩"修复证据链"失去 git 支撑**（文档本身还在，但 commit 引用失效）。
- 8 个核心文件在飞未提交，其中 core/prompts.py（skill 路由表瘦身+锁死下载）、core/main_agent.py（失败埋点）是解题能力核心改动——不提交 = 可能被覆盖丢失。
- ⚠️ 恢复旧对象库有**密钥回灌风险**（filter-repo 曾清除 1715a15 密钥历史，3.3G 备份含旧历史），**不建议强行恢复**，应以"重建基线 + 文档快照"重建证据叙事。

### 问题 4（外部阻塞）：平台 40403，无赛可打
- 今天 11:09 实测：pro.dasctf.com 可达、token 有效格式、但所有端点返回"无权操作"。测试赛已关、初赛已过、无开放赛事。
- 后果：AGENTS.md 唯一判据（真实平台 accepted）**当前无法满足**——一切"解出数提升"表述都被红线卡住。但这**不阻塞离线真题消化**（dry-run 用真值 flag 判分，是决赛能力的预演）。

### 问题 5（纪律余毒）：token 自爆事故
- 8/22 并行会话攻 xuanhun_ezip 绕开现成 skill 手搓 Z3 → bkcrack 版本坑 → 盲爆，单题投入超整场预算。
- 已修：AGENTS.md 第七節 R1-R6 + `core/prompts.py::SOLVE_DISCIPLINE` 运行时注入（本次实测已在代码里）。

## 三、以解题数为第一目标的作战路径（杠杆排序）

> 解题数 = 决赛现场平台 accepted 数。当前 0。以下按"每投入一分，最可能多解一道题"排序。

### 杠杆 1：把 32 道正式赛真题逐个吃透 → 沉淀确定性 skill（占 60% 权重）
**原理**：presolve 预扫不依赖 LLM 决策质量（教学型 91.7% 就是证明），且不烧 token。**决赛遇到同考点新题，确定性 skill 是唯一确定拿分的路径。**
- **静态可解组（9 题，先拿）**：crypto 2 + misc 3 + reverse 3 + pwn 1。逐一：dry-run → 失败分类 → 沉淀 skill → 回归绿。目标：**9 题里解出 ≥5，每题一个确定性流程落库**。
- **web 动态组（23 题，决定上限）**：静态审计已完成（攻击面=版本→CVE 已产出）→ 主攻 `web_target_interact` 靶机协议打通（本地 mock 靶机演练 HTTP/HTTPS/代理/槽位诊断）→ 决赛现场第一波抢简单动态题。目标：**保住 1-3 题**。
- 验收指标：回归索引里每题状态从 `unsolved` → `presolve/LLM 命中 + 真值判分通过`。

### 杠杆 2：真实 LLM 决策质量 17% → 40%（占 25% 权重）
**原理**：M2-M5 计划已批准（12:05 plan 模式），回归尺子已立（M1 完成，185→190 门禁绿）。这是"装弹"工程。
- **M2（立即）**：跑 15 题 questions_real 真实 LLM 基线（有真值 flag 可判分，每题 ≤300s，烧 DeepSeek 额度）→ 产出 4 类失败分布。
- **M3**：按失败模式改 `prompts.py` / `phases.py` / `goal_directive.py`（Web 决策树 → web plan → supervisor redirect → extract_flag 多格式容错 4 级杠杆点已定位）→ 每次改动后真题回归。
- **M4**：47 题全量 dry-run（含 race_details 33 题链路验证，无真值只验证"能跑到提交"）。
- 验收指标：questions_real 15 题 LLM 解出 ≥6（40%），且 4 类失败分布有向收敛证据。

### 杠杆 3：流程零事故保障（占 10% 权重，不直接得分但防归零）
- 收口在飞改动：审阅 8 文件 diff → commit（今天必须做，防丢失）。
- git 证据叙事重建：接受重建基线，在答辩文档中把"commit 引用"改为"文档 + 磁盘产物 + pytest 门禁"三重证据（commit 号仅作历史记录）。
- 平台 40403：向用户确认 8/22 后是否有开放赛事 + 正确 access key；有赛即跑 e2e 真实验收（accepted ≥1 才算数）。

### 杠杆 4：纪律持续生效（占 5% 权重）
- R1-R6 + 租约执法层已机器化。剩余动作：xuanhun_ezip flag.png 按已留药方续攻（同密码先验 ≤2min → PNG 头已知明文 bkcrack ~5min → 有界爆破），严禁重走 Z3。

> **项目不是"废了"，是"武器库已满、靶子还没打"**：工程从 0 分事故修到了门禁 190 绿 + 回归尺子 47 题 + 纪律机器化，但解题数仍为 0——因为 (a) 正式赛 32 道真题还没变成可判分的解出，(b) 23 道 web 动态题的靶机交互是唯一出路且未验证，(c) 真实 LLM 决策质量 17% 待 M2-M5 提升，(d) 平台当前无赛可打无法真实验收。
