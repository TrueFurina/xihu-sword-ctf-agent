3.1 战略定位 A-

最正确的判断：反共识。「Most CTF agents are just an LLM with a shell. This one is the opposite」——README 开篇就点破了行业通病。确定性优先（presolve 静态分析 → 51 skills → LLM 最后兜底）意味着可复现、可调试、成本可控、不吹牛，这四点在开源安全工具里是真正的护城河。

最致命的误判：把测试赛当战斗力信号。测试赛 7/7 800 分（独立已闭赛事）被长期当作「能打」的证据，掩盖了正式赛链路（幽灵变量、多进程互踩、403 WAF、LLM 熔断）从未真正在赛时验证过的事实。8/21 初赛 0 解出不是偶然，是「演练环境与实战环境脱节」的必然结果。

当前定位漂移：初赛已出局、无开放赛事，项目事实转入「开源方法论输出 + 来年复赛备战」轨道（已有《明年复赛夺冠作战计划》），但 README 仍以参赛叙事为主，两套叙事并存。

3.2 技术架构 B+

亮点：supervisor 架构（计划 → 步预算 → 工具优先 → 失败分类）、presolve 单点收敛（消除 5 处重复嗅探）、白名单 LLM + 401/402 熔断 + 墙钟止损、沙盒 AST 白名单 + 子进程隔离、5 道硬门禁全部 fail-closed。这些工程决策的成熟度远超一般 CTF 脚本项目，`test_deterministic_chains`、`test_merge_gate_failclosed` 等测试命名即见方法论。

硬伤：

  • 偏科 crypto_toolkit 1274 行 / math_engine 913 行 vs web_toolkit 仅 290 行——能力结构是「密码学工具箱」而非「CTF 全科 agent」
  • 监督者单薄 supervisor_agent 仅 196 行，LLM 环节在真题集上贡献 0——「智能体」名不副实
  • 数据断链 HGAME2022 三题的外部源目录已消失、附件无备份，台账中 4 条外部真题不可复核
  • 环境脆弱 .venv 曾指向已删除的 miniconda3 导致全链路击穿，8/26 才补上 setup.sh 三重自愈校验

3.3 真实能力（诚实口径）C

能力 = 静态分析器覆盖度，这是项目自己承认的。把数字拆开看：

  • 真题集 14/15 是 presolve 直出（其中 reverse_js / gongye_web2 是源码 grep 明文，2ms/7ms）——代表「模板覆盖度」，不构成「解出」
  • offline_verified = 9 中，5 道（specialcurve2/10732/10733/vnctf/10735）是完整攻击链独立核验，扎实；4 道（anwang/ezrsa/simplelegendre/ezmult）是 8/27 凌晨方案 A 从「presolve 确定性管线」迁入——真实密码学变换、flag 已落盘、双源验证，技术上成立，但口径经历了「不算 → 算」的放宽（详见矛盾 3）
  • 正式赛真题 33 道只攻下 3 道，web 类 0 道——对「西湖论剑决赛」这个真实目标而言，能力覆盖不到 10%

结论：这是一个称职的 crypto/misc 离线解题工具箱，尚未成为通用的 CTF agent。

3.4 工程治理 B-

方法论（本项目最大产出）：TOP0 总账（登记优先/写前持租约/完工回填/在飞禁令）+ 多智能体协同纲领 + CTDE 协议 + git hook 执法层，四层治理闭环。「单一事实源原则」「当文档与记忆冲突时以台账 commit 证据为准」——这套框架本身就是可复用的多智能体协作规范。

执行层失守记录（白纸黑字）：

  • 在飞改动禁令「已两次中招」→ 8/26 质检又抓到 MM 夹生文件 → 本次评估再次发现 4 个未提交 M + 4 个未跟踪目录（config.py 模型切换 + research-wiki 更新，改动本身合理，但未走登记-租约-提交流程）
  • git 事故 3 次：8/22 对象库损坏重建、8/25 checkout 误操作 prune 掉整条 master 提交链、8/26 坏 multi-pack-index 制造「数百对象缺失」假阳性——同一仓库 8 天内三次伤筋动骨
  • 收尾报告（8/26 23:06）宣称「工作树干净」，本次实测并非如此——报告与现实的时差本身就是治理问题

判断：机器执法层（hook）有效，人的纪律层（多会话自觉登记）反复失效。治理文档的「仪式密度」已经高于「执行实效」。

3.5 诚实性 A

这是本项目最值得公开传播的价值：

  • README 顶部挂 Honesty disclaimer，明示「0 accepted，不声称 LLM 自主推理」——同类项目几乎没有敢这么写的
  • 台账四套防线：平台 accepted 与离线核验严格区分、明文 flag 一律 <REDACTED sha256>、verified_flags.json gitignore、merge_gate 棘轮只升不降
  • 8/25 自查把「虚高 7」主动挤水回「真实 5」，8/27 再收敛到 9——口径在收紧与放宽之间来回，但每一轮都留有书面裁定与证据
  • 撤销记录完整：benchmark 37/49、web 10/10（本地硬编码靶机）、manifest 直接给答案——全部白纸黑字撤销

代价：诚实挤掉了「好看」。但这恰恰是项目未来最硬的资产——在 AI 安全领域，可信度比数字大。

3.6 安全 C+

  • 好 真 flag 脱敏链路完整（.gitignore 加固 3 轮，防嵌套否定规则覆盖）、密钥扫描门禁、git 历史清理
  • 坏 PAT 泄露 2 次：ghp_pCpo…（已吊销，8/26 18:07 复探 401）与 ghp_wGOy…（待用户手动轮换，风险登记在册）；ak_live 曾明文进 git 历史；周更自动化令牌与被暴露 token 未解耦，下次周日同步可能 401 停更
  • 结构性风险 本地沙箱 master 含明文真 flag 附件，与公开仓长期分裂——任何误推都会泄露真题真值，目前靠纪律而非机制约束

3.7 文档与知识管理 B-

文档量惊人（deliverables 79 文件、research-wiki 14 篇），方法论沉淀充分；但 RDD（文档通胀）反复发作：KPI 曾同时存在 13/14/15 三套口径、_INDEX 声称根目录 8 项实测 11+、总账锚点「父目录非 git 仓库」被实测推翻（父目录就是仓库根，research-wiki 已入库）。文档的更新速度追不上仓库的演化速度——这本身就是多会话并发时代的核心治理难题，项目没有彻底解决。

3.8 开源价值 B

公开仓 `TrueFurina/xihu-sword-ctf-agent` 布局规范（根级 tools/verify/web + ARCHITECTURE.md + CONTRIBUTING + issue 模板）、真值已脱敏、CI 全绿。但存在双仓分裂：公开仓 main（c7dfc42）缺 SSRF break 修复（本地 7703a89 已含），周更自动化是唯一的同步通道——这个单点通道的令牌还有风险（3.6）。PR #104（awesome-ai-agents-security）挂着未动，纪律上「不灌水」是对的。

4五大结构性矛盾（锐评）

矛盾 1「AI CTF Agent」之名 vs「LLM 推理 0」之实

项目名带 agent，架构有 supervisor/main_agent/LLM 客户端，但真题集上 LLM 真推理贡献 = 0，初赛 0 解出时 LLM 链路还整体熔断。真实能力 = 51 个确定性 skill + 正则 + 静态审计。这不丢人——但定位必须更早、更狠地说清：这是「确定性求解器框架 + LLM 兜底接口」，不是「AI 智能体」。继续用 agent 叙事，就会持续被「为什么 AI 不推理」拷问；改用「工具箱」叙事，9/14-15 的覆盖度反而体面。

矛盾 2治理仪式密度 vs 执行实效失衡

四层治理、六门禁、TOP0 总账、租约、棘轮——方法论密度接近「治理秀」级别；但 8 天内：git 事故 3 次、在飞改动至少 4 次、KPI 4 套数字并存、收尾报告与实际状态不符。机器 hook 拦得住 commit，拦不住「改不提交、改不登记、改文档不更新」。治理的终极问题不是写多少规范，而是每个并发会话是否真的先登记再动手——现状是这套纪律只在 Gu 亲自坐镇时生效。

矛盾 3KPI 口径的「严格性通胀」：5 → 9 的逻辑张力

8/26 质检：台账 5 是唯一真值，8/10 是纸面数字。8/27 凌晨方案 A：把 4 道 presolve 直出题迁入台账 → 9。技术上都对（这 4 题是真攻击链、flag 落盘、双源验证），但台账第四节曾白纸黑字「presolve 抽答案不算解题数」（针对 12/15 中 7 道 flag{} 格式题）。两处口径存在张力：「presolve 直出」到底算不算 offline_verified？按攻击链算，4 道该进；按「非 LLM 推理」算，9 道全都不该进。现在缺一条可机器判定的边界规则（例如：flag_scan 类 grep 不算；密码学变换类算），否则下次又会漂。

矛盾 4比赛窗口关闭后的真空期

初赛出局、无开放赛事，「解出」永远无法转化为平台 accepted。项目在「复盘过去（西湖论剑）」与「备战未来（明年复赛）」之间摇摆：既没有当下的竞技目标，也没有清晰的年度路线图（只有一份 4 周打 81.9% 的冲刺方案和一份明年夺冠计划）。真空期最危险的不是没进展，而是用文档密度制造进展幻觉。

矛盾 5web 短板是数据问题，不是工具问题

报告反复说「web 工具链已非瓶颈，缺真实靶机/赛题」——对，但这不是免责声明，而是数据工程欠账：crypto 有 15 道真题集 + 附件可供离线训练，web 为什么没有同规模的真题 benchmark？因为收集、脱敏、编排历史 web 真题的工作没人做。「没有赛」从来不是理由，crypto 的 15 道就是手工攒出来的。web 0/10 的真实根因是数据投入不足。

P0 · 安全收口（用户手动）

到 GitHub 控制台吊销并轮换 ghp_wGOy… PAT；确认周更自动化（automation-1787735803591）的 $GITHUB_TOKEN 与被暴露 token 解耦，否则下次周日 21:00 同步将 401 停更。这是当前唯一高于一切代码动作的项。

P0 · 收口本次实测的在飞改动

当前工作树有 4 个未提交 M（ctf_agent/config.py 的 qwen3.7-flash 免费模型切换 + research-wiki 3 文件）和 4 个未跟踪项（idea-stage/、research-wiki/ideas/、papers/）。改动内容合理，但必须走「登记 → 租约 → 提交」流程，不能让「改不提交」第 N 次成为下一份质检报告的素材。

解决矛盾 3：在台账写死「flag_scan/grep 明文类 = 不算；密码学变换类 = 算；题面直接给答案 = 不算」，并让 merge_gate 按规则数数。9 这个数字从此不再依赖凌晨裁定，而是规则的自然结果。

参考 crypto 的 15 道攒法：从历年公开赛事收集 web 真题（源码包 + 靶机快照），脱敏编排成 data/questions_real/web/，让 web_toolkit 的 8 类路由有真实对象可打。这是把 web 0/10 从「没赛可打」变成「可离线练」的唯一路径。

P2 · 让 LLM 推理贡献从 0 破冰

P2 · 文档收敛 + 双仓同步机制化

刷新 _INDEX.md（根目录实测 11 项）；把「本地沙箱永不 push 公开仓」从纪律升级为机制（例如公开仓发布走专门的脱敏导出脚本，替代人工 sync_to_public.py 单点）；SSRF break 修复尽早经周更通道合入公开仓。
