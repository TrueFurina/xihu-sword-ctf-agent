0.2 战略假设：把不可控目标换成可控目标

「赢 2027 复赛」是不可控目标（对手、题目、平台风控、运气）。可控的是：在 40+ 道真题上的解出率、LLM 推理贡献数、成本、可复现性、可审计性。本规划全部目标均可控、可测、可验收。赢是这些指标的副产品，不是规划对象。

0.3 决策分支：决赛窗（8/31 前晋级）

0.4 四条铁律（违反即回炉）

  • KPI 单一口径：唯一 KPI = merge_gate 机器数出的 offline_verified。任何文档、commit、口头不得自创数字。
  • 诚实红线：一切「解出」必须答得上「真题集真实链路解出几道」；web 短板未解前不报「全题型通杀」。
  • 反 RDD：每份新文档必须有生命周期（制定日 + 复审日 + 归档条件）；规划执行完即归档，不堆文档。
  • 机器判定优先：口径、门禁、在飞检查全部进 hook/脚本，不依赖会话自觉。

战役 ALLM 破冰（0 → 8）—— 最高杠杆，决定「agent」名实

问题：LLM 真推理贡献 0 是五大矛盾之首。不是没接模型（5 免费源 + deepseek 已通），是主 Agent 从没在真题上完成过一轮完整推理。

  • A1 闭环教材：10732 / 10733 / 10735 三题已离线解出，逆向为「LLM 推理路线图」（提示词 + 中间产物 + 工具调用序列），作为验收基准
  • A2 无兜底训练集：抽 8-10 题禁用 presolve 路由，强制裸推理，三类失败归因（工具缺失/提示词退化/模型上限）
  • A3 结构化归因：每轮失败产出 error_category + key_info + suggestion，下一轮定向修正——把「再试一次」变「告诉它错在哪」
  • A4 升级链路：轻量（qwen3.7-flash 免费）→ 失败×2 → 重型（deepseek-reasoner）→ 仍失败 → 监督者止损
测量：LLM 贡献题数（台账）· 每题 token 成本（预算熔断后 ≤ 1 元/题）· 平均步数（目标 ≤ 20 步/题）· 失败信号：2 周内破冰题仍为 0 → 降级为「纯工具链叙事」，砍掉 agent 宣传语

问题：矛盾 5：web 短板是数据欠账不是工具问题。crypto 的 15 道真题是手工攒的，web 为什么没有？

  • B2 脱敏编排流水线：描述 + 附件 + flag 真值 sha256（复用现有 verify_real_questions.py 守卫），杜绝明文真值入库

战役 D治理机制化 —— 让「第 N 次中招」成为历史

问题：矛盾 2：hook 拦得住 commit，拦不住改不登记、改不提交、改文档不更新。8 天内 git 事故 3 次、在飞改动 4+ 次。

  • D2 危险操作 SOP：checkout 跨分支 / reset / rebase / gc 前的 check-list 脚本（上次 checkout 事故就是无保护操作）；高危命令包一层 wrapper 拦截
  • D3 口径机器化：offline_verified 边界规则（flag_scan 类不算 / 密码学变换类算 / 题面泄露不算）直接写进 merge_gate 计数逻辑
  • D4 文档生命周期：_INDEX 自动比对目录树；90 天未更新且被新文档取代的 → 自动标「已归档」

战役 E赛时可靠性 —— 明年复赛的生死线

问题：8/21 初赛 0 解出的根因不是能力，是赛时链路（幽灵变量/多进程互踩/403 WAF/LLM 熔断）从未真实验证。测试赛 7/7 是假信号。

  • E1 赛时链路专项测试：模拟赛时环境（干净 env + 多并发 + 限速 + 代理抖动），回归「幽灵变量/多进程互踩/403 风控」三类事故
  • E2 环境快照与回滚：赛前生成 venv + 配置 + provider 快照，赛时 5 分钟内可回滚到已知良好态

触发：Phase 1 结束（9/30）破冰题仍为 0。对冲：立即降级为「纯工具链叙事」——公开仓删除 agent 宣传语，改称 deterministic solver framework；O1-KR2 目标从 8 调整为 0（诚实优先于好听）。这会让项目更小，但更真实。

高无赛可打的验证缺口（accepted 永远无法闭环）

本质：offline_verified 再高，也无法证明「平台上能 accepted」——8/21 已证明两者可完全脱节。对冲：模拟赛制度（E3）是唯一近似手段；答辩口径坚持「离线核验 + 模拟赛」，永不把离线数字冒充平台战绩（诚实红线已锁死）。

中token 成本失控（熔断未落地前提前开跑 LLM 训练）

触发：Phase 2 在熔断未实现时大量跑重型模型。对冲：Phase 1 破冰只用免费源 + 单题硬上限；熔断（Phase 3）落地前，LLM 训练量控制在每周 ≤ 20 题。

中双仓再次分叉（本地 9 分与公开仓 v1 脱节）

触发：脱敏导出脚本（Phase 3）交付前公开仓停更 > 1 个月。对冲：Phase 0 先确认周更自动化令牌有效；Phase 1-2 期间公开仓以「周更自动同步」维持呼吸，重大修复（如 SSRF break）手动补推。

中规划执行依赖 Gu 在场（治理单点）

触发：Gu 不在场期间会话又绕过流程。对冲：D1 机器扫描 + D2 高危命令 wrapper 让「不依赖自觉」成立；规划本身登记进总账，成为所有会话的引用锚点。
