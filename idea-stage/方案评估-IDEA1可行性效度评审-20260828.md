## 三、三大阻断性缺陷（修掉前不可执行）

### 缺陷 A：Benchmark 标签与 honesty 框架冲突 → 主指标失效
方案 Claim 1–3 的主指标都是"解出率"，并自称在 **"40 道西湖论剑真题"** 上跑。
- 磁盘实测：`data/questions_real/`（真真题）= 92 回收语料 / **15 精选 KPI 分母**；`data/questions/` = 53 文件，其中 **41 个 `self_authored_training`**（自产教学题，honesty 框架 §四 明令**不计分、当战绩=造假**）。
- "40 真题"≈ 那 41 道自产题。**自产题的 flag 自定、答案常写在题面 description 里** → 解出的不是"推理能力"而是"阅读理解"。用这 40 题跑出的任何"解出率提升"都是伪结论。
- 即使改用诚实 15 题：`offline_verified=12` 中 **13/15 由 presolve 静态直出，LLM 真推理贡献 0/12**。消融 LLM centric 组件（归因/监督/并发）在 LLM 路径几乎不被触发的 benchmark 上，**信号≈0，无法证伪任何 Claim**。

### 缺陷 B：离线 ≠ 真实赛场 → 答不了"真实运用"
- 整个实验是**离线历史解出率**。honesty 框架自身写明：**平台 live accepted = 0**。
- 方案**没有 live-platform 验证臂**。即便消融"成功"，也证明不了真实竞赛表现——而你要的恰恰是"真枪实战帮助 AICTF"。这是最致命的迁移断裂。

### 缺陷 C：无基线、无重复、无污染自检 → 数字不可信
- 成功判据（解出率 +20% / Token 省 40% / 并发 2–3x / 重试 +30%）是**凭空设定的目标值**，从未先报一个实测基线。没有基线就无从谈"提升"。
- "每种配置跑 1 次"——LLM 有温度非确定性，**单跑无种子、无方差、无置信区间**，不可下统计结论。
- 无污染自检（G1：历史题 writeup 公开、在预训练语料内）。方案未包含"RAG-off 重测"来隔离记忆污染。

## 五、Go / No-Go 与放行条件

**当前：NO-GO。** 放行需同时满足：

1. **重定 benchmark**：只用诚实 **15 题 KPI 分母**（或外部无污染集），**禁用 40 自产题**；或增加 live-platform 微验证臂（哪怕 3–5 道真赛题）。
2. **先建并发层（C3）**：这是最大缺口且阻断 Block 2，必须先落地 `asyncio.Semaphore` + 优先级队列 + 失败重入。
3. **先报实测基线**：跑一遍"全关"配置拿到基线数字，再谈 delta；每配置 ≥3 种子重复 + 报 CI。
4. **加污染自检**：RAG-off 重测，隔离记忆污染（G1）。
5. **分拆开发 vs 实验**：8 天开发计划和实验计划拆成两个 gate，开发完成且单测绿后再进实验。

## 七、给实战运用的真话

这套方案的**真实价值不在"跑出漂亮数字"**，而在它已落地的两块：
1. **纯规则 race-intelligence 引擎**（confidence / marginal_value / decision_engine，零 LLM）——这是可立刻用于实战的"赛时资源调度脑"，不需要等实验。
2. **诚实计量工程**（反注水法令 / merge-gate / 三层水位）——这是领域空白，本身值得写成方法论短文。

要"真枪实战帮助 AICTF"，**先把 race-intelligence 引擎接到 live 平台的 `--compete` 链路跑一轮真实提交**，比先写 8 天新功能 + 跑离线消融更接近你要的目标。
